4.1

Demand paging

Load the page when the process first needs it and again if it has since been evicted.

A program uses virtual addresses. The OS and memory-management unit (MMU) map each resident virtual page to a physical frame of the same size. The process can run with only part of its address space in RAM. Its page table preserves the mapping wherever the OS places each resident page. A valid nonresident page can be filled from its backing source, such as an executable or swap. A newly allocated anonymous page can instead be filled with zeros.

Virtual memory and its advantages

Virtual memory separates the logical memory a program sees from the physical memory actually installed. Each process gets its own large, contiguous-looking virtual address space. Only the parts in use need to be in RAM, and the rest stays on secondary storage until needed. Demand paging is the usual way to implement it.

  • Programs are not limited by RAM size. A program can be larger than physical memory, and programmers need not use overlays.
  • More processes fit in memory. Each process keeps only its active pages resident, so the degree of multiprogramming rises. CPU utilization and throughput rise with it, as long as the active pages still fit (see thrashing).
  • Less I/O to load or swap. Unused code, such as error-handling routines, is never read from disk. Programs start faster.
  • Sharing. Shared libraries and shared memory can be mapped into several address spaces using the same physical frames.
  • Faster process creation. Copy-on-write lets fork() share pages instead of copying the whole address space.
  • Sparse address spaces. The heap and stack can grow into the unused gap between them without RAM being reserved for it.

Think of RAM as the space available on a desk. You can work through a large book with only the pages for the current problem spread out. If you use the same pages repeatedly, you rarely go back to the shelf. This pattern is locality of reference. Temporal locality means a recently accessed page is likely to be accessed again soon. Spatial locality means nearby addresses are likely to be accessed soon. Paging brings a block of nearby addresses into RAM together.

What happens on an access?

The MMU looks up the virtual page and checks permissions. If the page is resident and the access is permitted, it uses the frame number with the original offset. In the demand-paging model, an access to a nonresident page traps to the OS. The OS checks its mapping and permission information to distinguish a legal absent page from an illegal access. Some slides call the residency indicator the valid/invalid bit. Read that indicator together with the OS’s separate knowledge of which addresses the process may use.

Fig 1. A legal demand fault can be serviced and the same instruction retried.
  1. Trap and check. The OS saves the faulting context. If the access is illegal, the OS reports the fault to the process, which may be terminated. If it is legal and the page is absent, the OS locates the backing data or determines how to initialize it.
  2. Obtain a frame. Take a free frame if one exists. Otherwise, choose a victim. If the victim is dirty, preserve its changed contents before reusing the frame. A clean victim with an up-to-date backing copy can be discarded. Mark the old mapping nonresident and invalidate any stale cached translation as needed.
  3. Fill and map. Bring in or initialize the requested page. The faulting process can wait while I/O completes, allowing another process to use the CPU. Update the page table and frame bookkeeping when the page is ready.
  4. Restart. Resume the faulting instruction so the access now succeeds. An instruction can touch several pages, which explains why architecture and restart behavior matter when deciding a minimum frame allocation.
Clarification in the slidesThe illegal-access branch applies to the offending process. The OS continues running. Restarting the faulting instruction is part of servicing a legal demand fault.

Pure demand paging starts the process without preloading its user pages. First touches can therefore fault. As the current set of actively used pages becomes resident, repeated accesses normally hit. Benefits include less initial loading and more opportunity to share RAM among processes. The cost is the delay of fault handling, particularly when it needs storage I/O.

Hardware support for demand paging

Demand paging needs the same hardware as paging and swapping, plus the ability to restart an instruction.

How does demand paging enable efficient memory usage in real-world systems such as multitasking operating systems, and what hardware support is required to make demand paging possible? A program has 10 pages but only 4 page frames are available. Explain how demand paging decides which pages to load into memory when a page fault occurs.

Answer outline
  1. Efficient memory use in multitasking (about 3 marks). Only the pages a process actually touches are loaded, so each process occupies only its working set. That lets more processes stay in RAM at once, keeps the CPU busy while some processes wait for I/O, shortens start-up, and lets processes share library pages. Use the advantages list above.
  2. Hardware (about 3 marks). Page table with a valid–invalid bit, swap space, instruction restart, plus reference and dirty bits. Use the table above, and draw Fig 1.
  3. 10 pages, 4 frames (about 4 marks). The process starts with all 10 entries invalid (pure demand paging). Demand paging does not guess. It loads only the page that caused the fault.
    • While a frame is free, the faulting page goes into that frame.
    • Once all 4 frames are full, a fault on any of the other 6 pages needs a victim. A replacement policy (FIFO, LRU, Clock…) chooses it, a dirty victim is written back, the victim's entry is marked invalid, and the new page is read in.
    • At any moment at most 4 of the 10 pages are resident. Pages that are never referenced are never loaded.

Effective access time (EAT)

Average the normal-access and fault paths using their probabilities. Read the question’s definition of the fault time. If it gives the total time on the fault path, use that as a single term. If it gives separate costs, add those costs as specified and include a victim write only where applicable.

EAT = (1 − p) × normal access time + p × total fault-path time p = page faults ÷ memory references

Copy-on-write (supporting topic)

Syllabus statusCopy-on-write is not named in the current Unit IV list. It is asked in the 2025–26 CIE-III (Q4b) and an older SEE (Paper F Q7a), so learn it as supporting material.

Copy-on-write (COW) lets several processes share the same physical frames until one of them writes. The shared pages are mapped read-only in every page table and flagged as copy-on-write.

  1. Reads by any process go to the single shared frame. No copying takes place.
  2. When a process writes to a COW page, the hardware raises a protection fault, because the page is mapped read-only.
  3. The OS sees the COW flag. It allocates a free frame, copies the page into it, and maps the copy read-write into the writer's page table only. Then it restarts the write.
  4. The other processes keep the original. When only one process still maps it, the OS can make that mapping writable again.

Only pages that can be modified need COW. Code and other truly read-only pages can simply be shared. The classic use is fork(). The child shares the parent's pages, so creating a process is fast. If the child immediately calls exec(), almost nothing is ever copied. The free frames used for copies are usually taken from a pool of zero-filled frames (zero-fill-on-demand).

2025–26 CIE-III Q4b · OS-CIE3-2025-26-B4b4 marks

A system uses copy-on-write for virtual memory. Analyze a scenario where multiple processes share a large read-only dataset. How does COW improve memory utilization in this case?

Answer outline
  • Setup. All processes map the dataset's pages to the same physical frames, marked read-only/COW. RAM holds one copy instead of one per process.
  • Reads. Because the dataset is only read, no write fault ever happens, so no page is ever duplicated. The saving lasts for the whole run.
  • A write (if one happens). Only the single page written gets a private copy for that process. The rest of the dataset stays shared, and the other processes are isolated from the change.
  • Effect. More free frames, so more processes or a larger cache fit in RAM. There are fewer page faults and less swap I/O, and new processes start faster because the dataset is never copied up front.

Constructed illustration: 4 processes each map a 2 GB dataset. Without sharing they need 4 × 2 GB = 8 GB. With COW they need 2 GB, plus one 4 KB page for each page a process actually modifies. That saves 6 GB.

4.2

FIFO replacement

Evict the page that entered memory earliest.

When a page fault occurs and the frame pool is full, a replacement policy chooses the page to evict. FIFO (first in, first out) keeps a queue in load order. Put each loaded page at the tail. A hit leaves the queue unchanged. On a full fault, remove the head, reuse its frame, and put the incoming page at the tail. The policy uses arrival time, so a page can be evicted even if it was used a moment ago.

Fig 2. The queue holds arrival order. A recent hit on A would leave it at the head.

Belady’s anomaly

For some reference strings, FIFO has more faults when it has more frames. Extra space changes which pages enter the queue and when, which can change later victims. FIFO lacks the stack property: at a given step, the resident set with fewer frames need not be a subset of the set with more frames. LRU and consistently traced Optimal have the stack property, so increasing their frame count cannot increase their fault totals on the same string.

How to show the workingMake an entry after each reference. Mark the initial loads as faults as well as evictions. Keep the frames in fixed slots so the overwritten slot is easy to see. Track the FIFO queue separately.

4.3

Optimal replacement

Evict the page whose next use is farthest away.

When a fault requires eviction, look to the right of the current reference. Find the first future occurrence of each resident page. Evict the one that will next be used farthest in the future. Treat a page with no future use as being infinitely far away. If several candidates are never used again, any of them gives the same minimum fault count.

Fig 3. Only the next use of each resident candidate matters at this fault.

Optimal (OPT or MIN) is a benchmark because it minimizes the number of faults for the given trace and frame count. Intuitively, keeping the page that will be needed sooner can only help before the farther-away page is used. We can exchange a different victim choice for the farthest-next-use choice without increasing total faults. A real OS generally does not know future references, while an exam question gives the whole string.

4.4

LRU replacement

Evict the page whose most recent use is farthest in the past.

Least recently used (LRU) assumes the recent past helps predict the near future. When replacement is needed, look to the left of the current reference. Find the most recent prior use of each resident page and evict the least recent. Alternatively, keep a recency list and move the accessed page to the front on every access, including a hit. This is the step that often makes LRU differ from FIFO.

Fig 4. A hit moves C to the front of the recency list without moving it between physical frames.
ImplementationWhat happens on a referenceHow the victim is found
Timestamp / counterWrite the current logical time into the page’s last-use field.Find the smallest last-use time. The basic method scans resident entries.
Recency stack / doubly linked listMove the accessed page to the most-recent end. With a direct node lookup, the move uses a fixed number of pointer updates.Take the least-recent end. The victim is directly available.

Both methods need to observe every reference to give exact order. Doing this on the ordinary access path is expensive. The shared recency order also explains why LRU avoids Belady’s anomaly. A cache with more frames keeps a longer prefix of that order, so every page held with fewer frames is also held with more frames.

4.5

LRU approximation

Keep a small record of recent use and consult it when a victim is needed.

A reference bit (R, also called the accessed bit) records whether a page has been touched since the bit was cleared. Hardware can set it on an access, so the OS need not rearrange a software list each time. A single bit distinguishes pages touched since the last clearing from those untouched in that interval. It cannot tell you which of several touched pages was accessed first.

Second chance and Clock

Second chance starts from FIFO order and gives a candidate with R=1 another turn. The Clock implementation organizes frames into a circle. When a full fault requires a victim, start at the hand. If the frame has R=0, evict the page. If it has R=1, clear the bit and advance. Continue until a victim is found. An ordinary access sets that page’s bit. In the trace below, a hit leaves the hand alone, and an insertion sets the bit and advances the hand.

Fig 5. Clock clears recently used candidates and stops at the first clear bit.

If all bits are set, one complete pass clears them and the hand returns to its original candidate. Clock then evicts that candidate. The decision follows circular order in this case. In general, Clock approximates recency because it remembers only whether a reference occurred since the bit was cleared.

Enhanced second chance

The modify bit (M, also called the dirty bit) indicates whether the page has changed since it was loaded or last written back. Enhanced second chance prefers the lowest available class in the table. When several pages share a class, the circular scan provides an order. The search may take several passes. Use the scan and bit-clearing rules given in the question if it asks for a step-by-step trace.

Additional reference bits (aging)

Aging keeps a short history for each page. At each timer tick, shift its history right, insert the current R at the most significant end, then clear R for the next interval. A recent touch adds more to the unsigned value than an older touch. Evict the page with the smallest history value. The OS can use a rule such as FIFO to break ties. Multiple accesses within one interval still appear as one bit.

Counting-based replacement: LFU and MFU (supporting topic)

Syllabus statusLFU and MFU are not named in the current Unit IV list. The 2025–26 CIE-III asked a 6-mark question on them (Q4a), so learn the idea and the two scenarios below.

Keep a counter of references for each resident page.

  • LFU (least frequently used) evicts the page with the smallest count. The reasoning is that an actively used page should have a large count. The weakness is a page used heavily early on and never again: its count stays high and it occupies a frame for nothing. A fix is to shift all counts right by 1 bit at regular intervals, which gives an exponentially decaying count.
  • MFU (most frequently used) evicts the page with the largest count. The reasoning is that the page with the smallest count was probably just brought in and has yet to be used.

Neither is common in practice. The counters are expensive to maintain on every reference, and neither policy approximates OPT well.

Conventions used in the traces belowA page's count starts at 1 when it is loaded, rises by 1 on each hit, and is discarded when the page is evicted. Ties are broken by FIFO, so the earliest-loaded page is evicted first. Use 3 empty frames. State your convention in the exam, because counts are sometimes kept across evictions.

Answer

MFU beats LFU after a change of phase. If old pages were used heavily and the program then moves to a new locality, the old pages keep large counts. LFU keeps those stale pages and keeps evicting the new pages (count 1) that are now in use, so it faults repeatedly. MFU evicts the high-count stale pages and keeps the new working set.

4.6

Allocation of frames

Decide how many frames each process gets and which frames are eligible for replacement.

If multiple processes need RAM, the OS has two decisions to make. Allocation assigns a share of the available frames. Replacement scope specifies which frames the OS can reclaim on a fault. Your desk space sets how much material you can keep at hand. The replacement rule decides which page leaves when you run out of space.

The available pool excludes RAM reserved for other uses. The instruction set and fault-restart model can impose a minimum number of resident frames per process. If one instruction and its operands touch several distinct pages, enough of those pages need to coexist for the instruction to finish. Otherwise, replaying it can evict a page that the same instruction will need again. This minimum is separate from the larger number a process may need to run efficiently.

Allocation schemeHow it divides the poolWhen it helps
EqualDivide available frames among the processes equally. For indivisible shares, state how remaining frames are handled.Simple when processes have similar needs. A very small process may be unable to use all its share.
ProportionalAllocate in proportion to each process’s size in pages.Gives larger processes a larger share. The size is only a proxy for the actively used pages.
PriorityUse priority as a weight, or combine it with size. Specify the weights and which priority is higher.Directs more memory to tasks that need preferential service.
m = available frames, n = number of processes, sᵢ = size of process i in pages Equal share = m / n Proportional share = m × sᵢ / Σsⱼ

Shares are real numbers until you turn them into integer frame counts. One choice is to take the floors and keep the rest in a free pool. If you need to distribute the full pool, assign remaining frames in descending order of fractional remainder, subject to minimums and usable page counts. An assigned budget can exceed the process’s need, but a process cannot keep more distinct pages resident than it has.

Local versus global replacement

Fig 6. The pool determines which pages a replacement policy can consider.

With local replacement, the faulting process evicts a page from its own allocation, so other processes cannot take its frames directly. Its performance is more predictable, although it can fault while another process holds frames it seldom uses. With global replacement, the victim can come from any eligible process. Frames can move to a process that is actively using memory, but one process’s faults can then take resident pages away from another. Priority-aware policies may limit which other processes are eligible.

4.7

Thrashing

The machine spends so much time bringing pages back that it makes little progress.

A process enters a new phase and touches a set of pages repeatedly. If its frames cannot hold that locality, one fault removes a page that another access will need soon. The next fault repeats the cycle. In a thrashing system, processes spend much of their time waiting for paging I/O and useful CPU work falls. Ordinary first-touch faults can be brief. Thrashing is sustained because the active pages cannot stay resident together.

As the degree of multiprogramming increases, the CPU can initially stay busier because another process can run when one blocks. If aggregate demand for active pages exceeds RAM, paging I/O rises and utilization drops. A scheduler that interprets low utilization as a sign that it should admit more work can amplify the problem. Under global replacement, a faulting process can take frames from another, shrinking the other process’s resident set and spreading the faults.

Fig 7. Qualitative behavior as competition for frames increases.

Working-set model

Pick a window of the last Δ page references for each process. Its working set contains each distinct page seen in that window. Its working-set size WSSᵢ estimates how many frames the current phase needs. A short window can miss active pages that are accessed less often. A long window can retain pages from an earlier phase and overestimate demand.

D = ΣWSSᵢ (total estimated frame demand) m = frames available to those processes If D > m, reduce the admitted load or suspend a process to free frames.

The model aims to keep the active sets of the running processes resident. When RAM is overcommitted, suspending one process can give the others enough room to finish useful work. Local replacement helps contain direct frame stealing. Processes can still contend for a shared paging device, so addressing the shortage itself matters.

Page-fault frequency (PFF)

PFF reacts to the measured rate of faults. Choose an upper and lower threshold. A process above the upper threshold should get more frames when available. If it is below the lower threshold, the OS may take back some frames, subject to its minimum. Between the thresholds, keep the allocation. If a process needs more frames and none are available, reduce multiprogramming. Working sets estimate demand from which pages were referenced. PFF looks at how often those accesses fault.

Quick revision

Use these prompts to reconstruct a full explanation before the exam.

If the question asks…Build your answer around…
How does demand paging work?Load on access, check legality, obtain a frame, preserve a dirty victim if needed, bring in and map the requested page, restart. Draw the flow and explain why locality helps.
What hardware does demand paging need?Page table with valid–invalid bit, swap space, instruction restart, plus R/M bits and a TLB in practice.
How does copy-on-write save memory?Share frames read-only, copy only the page that is written, on its protection fault. Shared read-only data is never copied.
What does FIFO evict?Oldest arrival. Hits leave queue order unchanged. Show a reference string with two frame counts for Belady’s anomaly.
What does Optimal evict?Farthest next use, with “never used again” ahead of any finite distance. Explain why the complete trace makes this a benchmark.
What does LRU evict?Oldest last use. Update recency even on hits. Explain a timestamp or recency-list implementation.
How does Clock approximate LRU?State the starting hand. Check R, clear and pass over set bits, evict at the first clear bit, then advance. Add the modify bit if asked about enhanced second chance.
When does MFU beat LFU?After a phase change (stale high counts). LFU wins when a stable hot set is mixed with one-time pages.
How does the OS share RAM?State the available pool. Compare equal, size-based and priority shares. State rounding and separate allocation size from the replacement pool.
Why does CPU utilization collapse?Repeated faults from undersized active sets keep processes waiting. Draw the curve and explain how working sets and PFF can reduce the load. For a working set, list the distinct pages in the last Δ references.
Before submitting a numericalMark the initial state and every fault. Count initial fills. Keep the frame count fixed for each run. A hit can change future decisions even though it leaves the resident pages in the same slots. Put times in one unit before averaging.
