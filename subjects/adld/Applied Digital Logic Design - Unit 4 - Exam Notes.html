Functional Units

The five functionally independent parts of a computer, how they cooperate, and what "stored program" means. U4 deck pp.2–3, 6

Start here · Notation & Operand-Order Refresher
  • Words & byte addresses: 1 byte = 8 bits; a 32-bit word = 4 bytes, so successive words sit at addresses 0, 4, 8, … (that is why PC increases by 4).
  • Register Transfer Notation (RTN): ← means "receives / is replaced by"; [X] means "the contents stored inside X"; double brackets [[PC]] mean "read the address stored in PC, then fetch what is in memory at that address".
  • Numbers & hex: #20 is the literal number 20 (immediate value), whereas 20 without # means memory address 20. Hexadecimal values are written 20h, 20H, 0x20 or $20 (2 hex digits = 8 bits = 1 byte).
  • Operand order warning: Most exam papers and Hamacher's ISA slides write Source first, Destination last Src → Dst, e.g. Move A, R0 copies A into R0. Some RISC, ARM, x86 and KB Ramesh examples write Destination first Dst ← Src. Every code block in this guide carries a tag showing which order it uses.

A computer accepts coded information, processes it according to a list of instructions, and returns results. Hamacher divides every computer into five functionally independent main parts: the input, memory, arithmetic and logic, output and control units. An interconnection network (in simple machines, a bus) lets these units exchange information and coordinate their actions.

Fig 1. The five functional units. The ALU, the control circuits and the registers together form the processor.

1.1 What each unit does

  • Input unit. Accepts coded information from human operators (keyboard, touchpad, microphone, camera) or from other computers over communication lines. Whenever a key is pressed, the corresponding letter or digit is translated automatically into its binary code and sent to the memory or the processor.
  • Memory unit. Stores programs and data across three layers:
    • Primary (main) memory — fast semiconductor memory built from 1-bit cells handled in groups of n bits called words. Each word has a distinct address, and any word can be reached in the same short memory access time, so it is a random-access memory (RAM).
    • Cache memory — a small, faster layer sitting between the processor and main memory to speed up frequent accesses.
    • Secondary storage — magnetic disks, SSDs, optical disks and flash; cheaper, larger, slower and non-volatile.
  • Arithmetic and logic unit (ALU). Executes arithmetic and logic operations (add, subtract, multiply, divide, compare). Operands are brought into the processor and held in high-speed registers, each storing one word.
  • Output unit. The counterpart of input: it sends processed results to the outside world (display, printer). Some units, such as a touch screen, do both input and output, and are called I/O units.
  • Control unit. Coordinates all the other units. It sends timing and control signals that say when a transfer happens and which operation is done. Physically, control is partly central and partly distributed through the machine; the signals travel over the interconnection network. How control is built is Unit V.

1.2 Instructions, data and the stored program

Information in a computer is either instructions or data. Machine instructions are explicit commands that (i) govern the transfer of information within the computer and between the computer and its I/O devices, and (ii) specify the arithmetic and logic operations to be performed. A program is a list of instructions for a task, and every instruction, number and character is encoded as a string of bits, because the hardware has only two stable states.

Both the program and its data are held in the memory. This is the stored-program concept: the processor fetches instructions from memory one after another and performs them, so the computer is controlled completely by the stored program, with no human intervention.

Exam answer: operation of a computer in four points
  1. The computer accepts information (programs and data) through the input unit and stores it in the memory.
  2. Information stored in memory is fetched, under program control, into the ALU, where it is processed.
  3. Processed information leaves the computer through the output unit.
  4. All activities inside the machine are directed by the control unit.
Check your understanding: why is the cache counted as part of "memory" and not as a sixth unit?

Its job is the memory unit's job, storing instructions and data. It is only a faster, smaller layer of that storage placed close to the processor. The memory hierarchy is covered in Unit V.

Basic Operational Concepts

The processor registers, the processor–memory connection with its three buses, and the steps by which one instruction is fetched and executed. U4 deck pp.4–5 U5a deck p.2 QB2 Q7

In this topic2.1 Three typical instructions2.2 Processor registers2.3 Processor–memory interconnection2.4 Executing one instruction

2.1 Three typical instructions

To perform a task, a program is stored in memory; individual instructions are brought into the processor, which executes them. Operands for the instructions are also stored in memory. A RISC-style processor uses three kinds of instruction for a simple calculation (these introductory textbook instructions use RISC operand order: Dst ← Src for Load and Add, and Src → Dst for Store):

InstructionMeaning (RTN)Notes
Load R2, LOC Dst ← SrcR2 ← [LOC]Reads memory location LOC into register R2. LOC is unchanged; the old R2 is overwritten.
Add R4, R2, R3 Dst ← SrcR4 ← [R2] + [R3]Operands in registers; R2 and R3 unchanged; the old R4 is overwritten.
Store R4, LOC Src → DstLOC ← [R4]Copies R4 into memory; the old contents of LOC are overwritten, R4 is preserved.

For Load and Store, the processor sends the address of the memory location to the memory unit and asserts the appropriate control signals; the data are then transferred to or from the memory.

2.2 Processor registers

RegisterRole

IR — instruction registerHolds the instruction currently being executed. Its output goes to the control circuits, which generate the timing signals for executing that instruction.

MDR — memory data registerHolds the data word being written to or read from memory; connects to the data lines.

2.3 Processor–memory interconnection

The connection between the processor and its memory consists of address, data and control lines. In the older textbook model these attach to the processor through MAR and MDR. If MAR is k bits wide and MDR is n bits wide, the memory can contain up to 2k addressable locations, and n bits are transferred in one memory cycle.

2.4 Executing one instruction

Every instruction goes through two phases: fetch and execute. Execution of a program starts when the PC is set to the address of its first instruction.

  1. Fetch. The contents of PC are sent to MAR and a Read is issued. When the memory responds (MFC), the word read is in MDR and is transferred to IR: IR ← [[PC]].
  2. Update PC. PC is incremented to point to the next instruction: PC ← [PC] + 4 for one 32-bit word in byte-addressable memory.
  3. Decode. The control circuits examine the IR to determine the operation and where the operands are.
  4. Execute. Operands are fetched (from registers, or from memory by sending their address to MAR and issuing Read); the ALU performs the operation; the result goes to a register, or to memory by placing the data in MDR, its address in MAR, and issuing Write.

This fetch–execute cycle repeats until the program ends. Normal execution can be pre-empted when a device raises an interrupt; the processor then saves its state, runs an interrupt-service routine and resumes (Unit V).

Add LOCA, R0 Src → Dst means R0 ← [LOCA] + [R0]; the operand at LOCA is in memory.

Memory is byte-addressable and each instruction occupies one 32-bit word, which is 4 bytes. The next instruction therefore starts 4 byte addresses later.

Performance: Technology and Parallelism

The basic performance equation, clock-cycle numericals, benchmark (SPEC) ratings, and the two ways speed improves: better technology and more parallelism. U4 deck pp.7–11, 44–46, 51

In this topic3.1 The basic performance equation3.2 Clock-cycle numericals3.3 SPEC rating3.4 Technology3.5 Parallelism

The most important measure of a computer's performance is how quickly it executes programs. A key design objective is the best possible performance at the lowest cost, so the price/performance ratio is a common measure of success. Speed depends on how fast instructions can be brought into the processor and how fast they can be executed. It is affected by the instruction set, the hardware, the software (including the operating system), the compiler that translates high-level programs into machine language, and the technology used to build the hardware.

3.1 The basic performance equation

Let T be the processor time required to execute a program written in a high-level language. The compiler produces a machine-language object program.

  • Let N be the number of machine instructions actually executed (the dynamic count: an instruction inside a loop is counted once for every pass, and instructions that are skipped are not counted).
  • Let S be the average number of basic steps needed to execute one machine instruction. Each basic step is completed in one clock cycle.
  • Let R be the clock rate in cycles per second (Hz). The clock period is P = 1/R.

The program needs N × S basic steps in total, and each step takes one clock period P. Hence

T = N × S × P = (N × S) / R seconds e.g. P = 1 ns ⇔ R = 1 GHz ; P = 1 µs ⇔ R = 1 MHz

To reduce T, reduce N or S, or increase R:

  • Reduce N — a good compiler, and more powerful instructions that do more work each. (This can raise S: a complex instruction needs more steps.)
  • Reduce S — simpler instructions, and especially pipelining, which overlaps the steps of successive instructions so that, ideally, one instruction completes every cycle (effective S ≈ 1); a superscalar processor issues several instructions per cycle (effective S < 1). See §13.
  • Increase R — faster circuit technology (smaller transistors switch faster), or dividing execution into more, shorter steps so the clock period can shrink.
N, S and R are not independentA RISC instruction set uses simple instructions (larger N, but small S and a fast clock); a CISC set uses complex ones (smaller N, larger S). The equation shows why these are trade-offs and why the only fair comparison is the measured total time T. The value of N and S also depends on the compiler.

Write the derivation above (definitions of N, S, R; N × S steps of one period P = 1/R each; T = N × S / R), then the three ways to reduce T. Example (illustrative values): a program executes N = 5 × 108 instructions, needing S = 1.6 cycles on average, on a 2 GHz processor:

Quick clock-rate ↔ clock-period conversions

Since P = 1 / R: 1 kHz ⇔ 1 ms (10−3 s) · 1 MHz ⇔ 1 µs (10−6 s) · 1 GHz ⇔ 1 ns (10−9 s). For any clock rate, T = total cycles / R = total cycles × P.

3.3 SPEC rating (benchmark programs)

The performance equation needs N and S, which are hard to know in advance. The practical measure is the time to run benchmark programs. The non-profit System Performance Evaluation Corporation (SPEC) selects representative application programs (games, compilers, databases, numerically intensive scientific programs). Each program is compiled and run on the computer under test and on a reference computer (for SPEC2000, an UltraSPARC10 workstation with a 300 MHz UltraSPARC-IIi processor).

SPEC rating = Running time on the reference computer / Running time on the computer under test Overall SPEC rating = ( SPEC1 × SPEC2 × … × SPECn )1/n geometric mean over the n programs

A SPEC rating of 50 means the computer under test is 50 times as fast as the reference computer for that benchmark. Because the measured time includes the compiler, the operating system and the memory, the rating reflects the whole system. Illustration (made-up times): three programs (n = 3) taking 500 s, 300 s, 900 s on the reference and 10 s, 12 s, 20 s on the test machine give ratios 50, 25, 45 and an overall rating of (50 × 25 × 45)1/3 = 38.32.

3.4 Technology

The technology of Very Large Scale Integration (VLSI), used to fabricate a processor on a single chip, is a critical factor in speed. The speed of switching between the 0 and 1 states is largely determined by the size of the transistors: smaller transistors switch faster. Decades of advances in fabrication have reduced transistor sizes dramatically, with two advantages: instructions execute faster (higher R), and more transistors fit on a chip, giving more logic (for example, more parallel units) and more on-chip memory such as caches.

3.5 Parallelism

Performance also increases when several operations are performed at the same time. Parallelism is implemented at several levels:

  • Instruction-level parallelism. Instead of finishing all steps of one instruction before starting the next, overlap the steps of successive instructions: fetch the next instruction while the current one is in the ALU. This is pipelining (§13). Superscalar processors go further and execute several instructions in parallel.
  • Multicore processors. Several processing units, called cores, are fabricated on one chip; "processor" then means the whole chip (dual-core, quad-core, octo-core).
  • Multiprocessors. Systems with many processors, each possibly multicore, which either run different tasks in parallel or the subtasks of one large task. All processors usually share access to all of the memory (shared-memory multiprocessor).
  • Multicomputers (textbook addition). Interconnected computers, each with its own private memory, cooperate by exchanging messages (message-passing multicomputers).
Check your understanding: a loop body of 10 instructions runs 50 times. What is N for that loop?

N counts executed instructions, so the loop contributes 10 × 50 = 500, even though the program text holds only 10 instructions.

In this topic4.1 Words4.2 Byte addressability4.3 Big- and little-endian4.4 Word alignment, characters and strings

4.1 Words and word length

Instructions (in binary) and data (numbers and characters in binary, BCD or ASCII) are stored in the memory. The memory consists of millions of one-bit storage cells, but they are rarely handled one bit at a time. The memory is organised so that a group of n bits can be stored or retrieved in a single basic operation. Each group of n bits is a word of information, and n is the word length. Common word lengths are 16, 32, 64 and 128 bits.

A 32-bit word can hold a 32-bit signed integer (bit b31 is the sign: 0 for positive, 1 for negative) or four 8-bit ASCII characters. Accessing the memory to store or retrieve one word, or one byte, requires a distinct address for each location.

4.2 Byte addressability and the number of address lines

Bits are grouped into bytes and words, and most modern computers give one unique address to each 8-bit byte. This is byte addressability. Addresses run from 0 to N − 1, where N is the number of byte locations, and N is set by the address lines the processor provides. With M address lines:

N = 2M bytes M = number of address lines (= address bits) 210 = 1K 216 = 64K 220 = 1M 224 = 16M 230 = 1G 232 = 4G 240 = 1T

So a 16-bit address reaches 64 KB, a 32-bit address 4 GB, and a 64-bit address 264 ≈ 16 × 1018 bytes (16 exabytes; in practice only a small part of that range is used). Intel's 8086 provides 20 address lines to reach 1 MB, because 220 = 1M. The set of all addresses is the address space. In a byte-addressable memory with 32-bit words, successive words are at addresses 0, 4, 8, …, and these word addresses are used for memory reads and writes of whole words.

4.3 Big-endian and little-endian assignments

A 32-bit word occupies four consecutive byte addresses. There are two ways to assign those byte addresses across the word:

  • Big-endian: lower byte addresses are used for the more significant bytes (the leftmost bytes) of the word. The most significant byte is at the lowest address. Example: Motorola processors.
  • Little-endian: lower byte addresses are used for the less significant bytes (the rightmost bytes). The most significant byte is at the highest address. Example: Intel processors.
  • Bi-endian: the processor can handle both styles; ARM supports both.

In both schemes the word itself has the same address: the lowest of its byte addresses (0, 4, 8, …).

4.4 Word alignment, characters and strings

With a 32-bit word, natural word boundaries occur at byte addresses 0, 4, 8, …; words that start there have aligned addresses. In general, a word is aligned if it begins at a byte address that is a multiple of the number of bytes in a word: 16-bit words at 0, 2, 4, …; 64-bit words at 0, 8, 16, …. Accessing an unaligned word may need two memory accesses, or may not be allowed at all, so compilers and assemblers keep data aligned.

A number usually occupies one word and is accessed by its word address. Characters occupy one byte each and are accessed by their byte address. A string of characters is stored in successive byte locations; its length is shown either by a special end-of-string character or by a separate count stored with it.

Memory Operations

The two basic operations every random-access memory supports. U4 deck p.16

Both program instructions and data operands are stored in the memory. To execute an instruction, the processor must bring the instruction (and usually its operands) from memory, and results must be written back. So two basic operations are needed:

Read — Load

Transfers a copy of the contents of a specific memory location to the processor. The memory contents remain unchanged. The processor sends the address of the location to the memory and requests a Read; the memory reads the data stored there and sends them to the processor.

Write — Store

Transfers an item of information from the processor to a specific memory location, destroying the former contents of that location. The processor sends the address and the data, and requests a Write.

In machine-language programs these operations are called Load and Store. An item transferred may be one byte or one word (several bytes); the control lines (§2.3) say which. How these transfers are carried out inside the processor, with MAR, MDR and the MFC signal, is shown step by step in Unit V.

What is an Instruction Set Architecture (ISA)?

The Instruction Set Architecture (ISA) is the interface between software and hardware—everything a machine-language programmer (or compiler) sees and must know to write programs for a processor:

  • the complete set of machine instructions and their instruction formats,
  • the programmer-visible registers and condition flags,

Different hardware designs can implement the same ISA. Common examples are ARM, Intel x86, RISC-V and MIPS.

6.1 Four types of operation

A computer must have instructions capable of performing four types of operations:

  1. Data transfers between the memory and the processor registers.
  2. Arithmetic and logic operations on data.
  3. Program sequencing and control (branches, calls).

6.5 Instruction execution, straight-line sequencing and branching

Suppose the three instructions of Move A, R0; Add B, R0; Move R0, C are in successive word locations starting at address i (byte-addressable, 32-bit words), so they are at i, i + 4, i + 8. To start, the address i is placed in the PC. The processor fetches and executes the instructions one at a time, in order of increasing addresses; this is straight-line sequencing. After the instruction at i + 8 executes, PC = i + 12, the first instruction of the next segment. Each instruction runs in two phases: instruction fetch (IR ← [[PC]], PC incremented) and instruction execute (decode, fetch operands, operate, store result).

To add a list of n numbers, a straight-line program needs n Add instructions (Move NUM1, R0; Add NUM2, R0; … Add NUMn, R0; Move R0, SUM). It is shorter to place a single Add in a program loop that runs n times. A register is used as a counter, and a branch instruction loads a new address, the branch target, into the PC. A conditional branch causes a branch only if a specified condition holds; otherwise the PC is incremented normally and the next instruction in sequence is fetched.

6.7 Encoding machine instructions

An instruction is stored as a binary pattern with fields: an opcode field identifying the operation, and fields identifying the operands (register numbers, a memory address or an immediate value).   • Logic instructions: AND, OR, XOR, NOT operate bit by bit, e.g. And #0FFh, R0 clears all but the low byte (masking).

Programs use data structures: constants, local and global variables, pointers, arrays, lists and queues. When a compiler translates a high-level program, it must implement these with the facilities of the instruction set. The different ways in which the location of an operand is specified in an instruction are called addressing modes. For a memory operand, the mode tells the processor how to compute the effective address (EA), the actual address of the operand.

  • Immediate (#20): hand your friend the number 20 directly.
  • Register (R1): "check pocket R1."
  • Absolute / Direct (1500): "open locker 1500."
  • Indirect ((R1)): "pocket R1 holds a sticky note with the locker number — open that locker."
  • Index (20(R1)): "take the locker number in R1 and walk 20 doors down."

7.2 Immediate, register and absolute modes

  • Register mode: the operand is the contents of a processor register; the register's name (address) is given in the instruction. Add Ri, Rj adds the contents of Ri and Rj and stores the result in Rj (Rj ← [Ri] + [Rj]). Fast, and needs only a few bits in the instruction. Used for intermediate results.
  • Absolute (direct) mode: the operand is in a memory location whose address is given explicitly in the instruction (EA = LOC). Move LOC, R2 moves the contents of address LOC to R2 (R2 ← [LOC]). Used for global variables: a declaration like Integer A, B; allocates fixed locations.
  • Immediate mode: the operand value itself is given in the instruction, marked with #. Move #200, R0 places the value 200 in R0 (R0 ← 200). No memory access is needed for the operand. Used for constants. (The # sign keeps it distinct from Move 200, R0, which is absolute mode.)

7.3 Indirection and pointers

In indirect mode, the instruction does not give the operand or its address directly. It gives a register or a memory location that contains the address of the operand. Indirection is shown by placing the register name or memory address in parentheses: EA = [Ri] (register indirect) or EA = [LOC] (memory indirect). The register or memory location that contains the address of an operand is called a pointer. Pointers let one instruction work on different data: change the pointer, and the same instruction reaches a different operand. For example, Add (R1), R0 with R1 = B adds the word at address B to R0 (R0 ← [R0] + [B]).

7.4 Indexing and arrays

In index mode the EA is generated by adding a constant value X, given in the instruction, to the contents of a register: EA = X + [Ri], written X(Ri). The register may be a special index register or, more commonly, any general-purpose register. The contents of the index register are not changed while the EA is formed. The mode suits lists and arrays in two ways: X is the start address of an array and Ri holds the offset of an element; or Ri points to the start of a record (a pointer) and X is the fixed offset of a field within it. Two variations:

  • Base with index (Ri, Rj): EA = [Ri] + [Rj]. The second register is usually called the base register. Both parts can change at run time; useful for a two-dimensional array.
  • Base with index and offset X(Ri, Rj): EA = X + [Ri] + [Rj]. Useful for accessing a field inside each item of a list of records (a three-dimensional structure).

7.5 Relative mode

Relative mode is index mode with the program counter used in place of a general-purpose register: X(PC), with EA = [PC] + X. 7.6 Autoincrement and autodecrement

  • Autoincrement (Ri)+: the EA is the contents of Ri (EA = [Ri]). After the operand is accessed, Ri is automatically incremented to point to the next item in a list (Ri ← [Ri] + 4 for 32-bit words).
  • Autodecrement −(Ri): the contents of Ri are first decremented (Ri ← [Ri] − 4), and then used as the EA (EA = [Ri]).

These modes step a pointer through a list without separate Add instructions (Add (R2)+, R0 replaces Add (R2), R0 + Add #4, R2), and together they implement a stack: Move NEWITEM, −(SP) pushes, Move (SP)+, ITEM pops (§9).

8.1 Assembly language

Machine instructions are binary patterns, which are awkward for people. A complete set of symbolic names (mnemonics such as MOVE, ADD, BRANCH) and rules for their use forms a programming language, an assembly language. The rules for writing statements are its syntax. A program written in assembly language is automatically translated into machine instructions by a program called an assembler. The user program in its original text form is the source program; the assembled machine-language program is the object program.

Each statement has four fields: Label Operation Operand(s) Comment. The optional label names the memory address where the instruction or data will be placed; the operation field holds a mnemonic or a directive; the operand field gives addressing information; the comment is ignored by the assembler. Numbers can be written in decimal (ADD #93, R1), binary (%01011101) or hexadecimal (0x5D or $5D). A suffix can also mark the mode, as in ADDI 5, R3 (immediate).

8.2 Assembler directives

Besides instructions, the source program must tell the assembler other information needed to translate it. Statements that do this are assembler directives (or commands, pseudo-operations). They are used by the assembler during translation; they are not translated into machine instructions and are never executed by the processor.

Stacks

A LIFO list in memory, the stack pointer, and push and pop with autodecrement and autoincrement. U4 deck pp.31–32 QB2 Q18

A stack is a list of data elements (usually words or bytes) with the restriction that elements can be added or removed at one end only, the top. The other end is the bottom. It works on the last-in, first-out (LIFO) principle. Placing an item on the stack is a push; removing the top item is a pop. A processor register called the stack pointer (SP) holds the address of the top element. By common practice the stack grows toward lower addresses, so in a byte-addressable memory with 32-bit words, a push decrements SP by 4 (SP ← [SP] − 4) and a pop increments it by 4 (SP ← [SP] + 4).

10.1 Subroutine linkage

A subtask performed many times, on different data, is written once as a subroutine. The program branches to it with a Call instruction; after the subroutine finishes, execution must resume at the instruction immediately after the Call, so the subroutine ends with a Return instruction. The way a computer makes calling and returning possible is its subroutine linkage method. The simplest method saves the return address in a dedicated register, the link register (LR):

  • Call: store the contents of the PC (which already points to the next instruction) in LR; then branch to the subroutine's address. LR ← [PC]; PC ← target
  • Return: branch to the address in LR. PC ← [LR]

10.2 Subroutine nesting and the processor stack

Subroutine nesting means one subroutine calls another. If the second Call also stores its return address in the link register, the first return address is destroyed. So the link register must be saved somewhere else before another call. Nesting can go to any depth; the last subroutine called is the first to return, so return addresses are generated and used in last-in, first-out order. That is exactly a stack. Many processors therefore do it automatically: the Call instruction pushes the contents of the PC onto the processor stack (the stack pointed to by SP) and loads the subroutine address into the PC; the Return instruction pops the return address from the stack into the PC.

10.3 Parameter passing

The exchange of information between a calling program and a subroutine is parameter passing. The parameters may be placed:

  1. In registers — straightforward and efficient, but the number of registers is limited.
  2. In fixed memory locations — simple, but the subroutine cannot easily be shared or called recursively.
  3. On the processor stack — flexible; handles a large number of parameters, and nesting and recursion.

By value or by reference. A parameter passed by value is the actual data (the count n). A parameter passed by reference is the address of the data (the address NUM1 of the list), so the subroutine can work on, or change, the caller's data in place.

The Stack Frame

In this topic11.1 Frame layout and FP11.2 Improvement-test frame11.3 Nested subroutines

During execution of the LISTADD subroutine above, six locations at the top of the stack contain entries needed by that subroutine. These locations form a private work space for the subroutine, created when it is entered and freed when it returns control to the caller. This space is called a stack frame. If the subroutine needs space for local variables, they too are allocated on the stack, inside the frame.

11.1 Frame layout and the frame pointer

SP moves whenever something is pushed or popped inside the subroutine, so offsets from SP keep changing. A second register, the frame pointer (FP), is set once on entry and stays fixed, giving convenient access to the parameters (positive offsets) and the local variables (negative offsets). Because the stack grows toward lower addresses, older items pushed before FP was set (return address, parameters) sit at higher addresses (+ offsets), while newer items allocated afterwards (local variables) sit at lower addresses (− offsets).

  1. The calling program pushes the four parameters onto the stack.
  2. The Call instruction pushes the return address; SP now points to it, and the first instruction of the subroutine is about to run.
  3. FP is a general-purpose register that may hold the caller's data, so its contents are saved by pushing them, and then FP is set to the current top: Move FP, −(SP); Move SP, FP. Now SP and FP both point to the saved FP.

12.1 ARM (a RISC architecture)

ARM processors are designed for low power and small size and dominate mobile and embedded systems. The classic 32-bit ARM ISA follows the RISC style of §6.4.

  • Registers. Sixteen 32-bit general-purpose registers R0–R15, three with special roles: R13 = SP (stack pointer), R14 = LR (link register), R15 = PC. A CPSR (current program status register) holds the condition flags N, Z, C, V, interrupt-disable bits and the processor mode.
  • Instructions. All are 32 bits long (a compressed 16-bit set, Thumb, improves code density). It is a load/store architecture: only LDR/STR (and multiple-register LDM/STM) access memory; data-processing instructions use three register operands, destination first (Rd, Rn, Op2): ADD R0, R1, R2 means R0 ← [R1] + [R2]. The second operand can be shifted in the same instruction: ADD R0, R1, R2, LSL #2 (R0 ← [R1] + 4 × [R2]).
  • Conditional execution. Almost every instruction can carry a condition (ADDEQ, MOVGT), executing only if the flags match; the suffix S (SUBS) makes an instruction set the flags.
  • Addressing modes (for LDR/STR), all based on a base register Rn: offset [Rn, #off] (index mode, EA = [Rn] + off), pre-indexed [Rn, #off]! (EA = [Rn] + off, then Rn ← [Rn] + off, like autoincrement/autodecrement), post-indexed [Rn], #off (EA = [Rn], then Rn ← [Rn] + off), register offset [Rn, Rm] (EA = [Rn] + [Rm]), and PC-relative for constants and branches.
  • Subroutines. BL target (branch with link) puts the return address in LR; return is BX LR (or MOV PC, LR). A nested routine first saves LR on the stack with PUSH {R4, LR} and returns with POP {R4, PC}.
  • Memory. Byte-addressable, 32-bit words, bi-endian (usually little-endian).

  • Memory. Byte-addressable and little-endian.

Overview of Instruction-Level Parallelism and Pipelining

Overlapping the steps of successive instructions; the cycle count of an ideal pipeline; what stops it (hazards); and superscalar issue. U4 deck p.8 (one paragraph)

Mostly not in your materials — added for syllabus completenessThe deck gives only the definition of pipelining (p.8, quoted in §3.5). The stages, timing chart, hazards and superscalar points below follow the textbook's pipelining chapter at overview depth.

Instruction-level parallelism (ILP) means executing parts of several instructions of the same program at the same time. The simplest way to run a program is to complete all steps of the current instruction before starting the next. If instead the steps of successive instructions are overlapped, total execution time drops. For example, the next instruction can be fetched while the ALU works on the current one. This overlap is pipelining, named after an assembly line: each stage does one part of the work and passes the instruction on.

Laundry analogy (latency vs throughput)

If washing, drying and folding one load of laundry each take 1 step, doing 4 loads one by one takes 12 steps, whereas overlapping them (starting load 2 in the washer as load 1 moves to the dryer) finishes 1 load every step after the first load completes. Each individual load still takes 3 steps from start to finish (latency is unchanged), but finished loads per hour triple (throughput rises).

13.1 Pipeline stages and timing

Divide instruction processing into k stages of one clock cycle each, with buffer registers between stages to hold the intermediate results. A common four-stage pipeline is F (fetch the instruction), D (decode and read the source registers), E (execute the ALU operation) and W (write the result). RISC processors often use five stages: fetch, decode, compute, memory access, write back.

Fig 16. Four instructions in a four-stage pipeline (F fetch, D decode, E execute, W write). In cycle 4, all four stages are busy with different instructions.
non-pipelined: n instructions × k stages = k·n cycles pipelined: first result after k cycles, then one per cycle = k + n − 1 cycles speed-up = k·n / (k + n − 1) → k for large n e.g. k = 4, n = 100: 400 vs 103 cycles, speed-up 3.88 ; k = 5, n = 1000: 5000 vs 1004, speed-up 4.98

Pipelining does not shorten the time of a single instruction (its latency); it increases throughput (instructions completed per second). In the performance equation T = N × S / R, ideal pipelining makes the effective S equal to 1.

13.2 Hazards: what stops the pipeline

Any condition that makes the pipeline stall (pause one or more stages) is a hazard.

  • Data hazard: an instruction needs a result that an earlier instruction has not yet written. After Add R4, R2, R3, the instruction Subtract R6, R4, R5 needs the new R4. Remedies: stall until it is written, or operand forwarding (send the ALU result directly to the next instruction's input), or let the compiler reorder instructions or insert NOPs.
  • Control hazard: after a branch, the instructions already fetched behind it may be the wrong ones. The lost cycles are the branch penalty. Remedies: compute the target early, branch prediction, and the delayed branch.
  • Structural (resource) hazard: two instructions need the same hardware in the same cycle, for example one memory for an instruction fetch and a data access. Remedy: separate instruction and data caches.
  • Cache misses also stall the pipeline while the memory responds.

13.3 Superscalar operation

A superscalar processor has several execution units (for example two integer ALUs, a floating-point unit, a load/store unit) and can issue more than one instruction per clock cycle, so the effective S drops below 1. It fetches several instructions at once, checks that they are independent, and dispatches them to different units; advanced designs execute instructions out of order when the data they need are ready, while keeping the results in program order. ILP is then limited by the dependencies in the program. The other forms of parallelism (multicore, multiprocessors) are in §3.5.

Check your understanding: why can't a 5-stage pipeline give a speed-up of exactly 5?

Filling the pipeline costs k − 1 cycles (k + n − 1 instead of n), and hazards cause stalls. The speed-up only approaches k for long runs of independent instructions.

ADLD-IMPROVEMENT-2025-26-B4a4 marks
Design and implement ALP codes using two-address and three-address instruction formats to compute y = x3 + 15x + 10, and comment on the efficiency of each approach.
Answer

Three-address (5 instructions)

MULT X, X, T ; T ← x² MULT T, X, T ; T ← x³ MULT #15, X, Y ; Y ← 15x ADD T, Y, Y ; Y ← x³ + 15x ADD #10, Y, Y ; Y ← x³ + 15x + 10

Two-address (7 instructions)

MOVE X, T ; T ← x MULT X, T ; T ← x² MULT X, T ; T ← x³ MOVE X, Y ; Y ← x MULT #15, Y ; Y ← 15x ADD T, Y ; Y ← x³ + 15x ADD #10, Y ; Y ← y + 10

Better: factor first (Horner form y = (x2 + 15)·x + 10), which saves one instruction in each format:

; three-address, 4 instructions MULT X, X, T ; T ← x² ADD T, #15, T ; T ← x² + 15 MULT T, X, T ; T ← x³ + 15x ADD T, #10, Y ; Y ← x³ + 15x + 10
; two-address, 5 instructions MOVE X, Y ; Y ← x MULT X, Y ; Y ← x² ADD #15, Y ; Y ← x² + 15 MULT X, Y ; Y ← x³ + 15x ADD #10, Y ; Y ← x³ + 15x + 10

Check: x = 2 → 8 + 30 + 10 = 48 from all four programs (verified for x = −5 … 7).

Efficiency. (1) Instruction count: three-address needs fewer instructions (5 vs 7; 4 vs 5 factored), because it names a separate destination and so needs no MOVE copies. (2) Instruction size: each three-address instruction carries three operand addresses (3k bits for k-bit memory addresses), so it is longer and may need more than one word; two-address instructions are shorter. (3) Memory traffic for operands (X, Y, T in memory): 13 operand accesses (three-address) vs 17 (two-address); 10 vs 12 factored. (4) Keeping x in a register (load it once) cuts memory accesses in both formats, which is what RISC load/store code does. Overall the three-address version is faster to execute; the two-address version gives more compact instructions.
