1.1

Number Representation

Part 1 — Arithmetic

A computer must represent both positive and negative integers using only bit patterns. Three classical schemes exist, and all three agree on one rule: the most significant bit (MSB) is 0 for positive numbers and 1 for negative numbers.

  • Sign-and-magnitude: the MSB is a pure sign flag; the remaining bits hold the magnitude unchanged. A negative value is formed by flipping only the MSB of the positive value. E.g. +5 = 0101, −5 = 1101.
  • 1's complement: a negative value is formed by complementing every bit of the positive value. Equivalently, the 1's complement of an n-bit number N is (2n−1) − N. E.g. −5 is obtained by complementing 0101 → 1010.
  • 2's complement: a negative value is formed by complementing every bit and then adding 1 — i.e. the 2's complement of N is 2n − N, or equivalently "1's complement + 1". E.g. −5: complement 0101→1010, add 1 → 1011.

2's complement is the representation used almost universally in hardware because it gives the most efficient addition/subtraction circuitry: a single adder can add two 2's-complement numbers of either sign with no special-casing, and there is only one representation of zero (unlike sign-magnitude and 1's complement, which both have a +0 and a −0).

Fig 1. 4-bit signed-integer representations — 2's complement gives one extra negative value and a single zero.
Exam tip For an n-bit 2's-complement number the representable range is −2n−1 to +2n−1−1 — note the asymmetry (one extra negative value, since 1000…0 has no positive counterpart).

1.2

Signed Addition, Subtraction & Overflow

Part 1 — Arithmetic

All addition and subtraction of signed numbers in 2's complement follows two simple rules, applied uniformly regardless of the operands' signs:

  1. Rule 1 (Add): add the n-bit representations of the two numbers and discard any carry-out of the MSB position. The result is algebraically correct provided it lies in the representable range −2n−1 to +2n−1−1.
  2. Rule 2 (Subtract X − Y): form the 2's complement of Y and add it to X using Rule 1.

When representing a signed number using more bits than it was originally stored in, the sign bit is repeated as many times as needed to the left — this is called sign extension, and it preserves both the sign and the numeric value.

Overflow

When the true result of an addition/subtraction falls outside the representable range, an arithmetic overflow occurs and the stored result is wrong. Two facts pin down exactly when this can happen:

  • Overflow can occur only when adding two numbers of the same sign (two positives or two negatives) — adding numbers of opposite sign can never overflow, since the true sum's magnitude is always bounded by the larger operand's magnitude.
  • The carry-out of the sign-bit position is not by itself a reliable overflow indicator for signed addition. The standard hardware detection rule is instead: overflow ⇔ carry into the sign bit ≠ carry out of the sign bit (equivalently, the sign bits of both operands match each other but differ from the sign bit of the result).
Fig 2. Adding two same-sign numbers can push the true sum outside the representable window on either side.
worked example — overflow, 8-bitverified
Add +127 and +1 in 8-bit 2's complement, and show the underflow case 0 − 127.
Solution
01111111 (+127) + 00000001 (+1) ----------- 10000000 bit pattern of −128 → overflow (both operands positive, result negative) 00000000 (0) − 01111111 (127) → add 2's complement of 127 (10000001) ----------- 10000001 bit pattern of −127 → correct here (0 − 127 = −127 is in range)

The first case overflows because two positives summed to a value ≥ 27; the carry into the sign bit (1) differs from the carry out of it (0), confirming overflow by the hardware rule.

Multiplication of Unsigned Numbers

Part 1 — Arithmetic

Manual (paper-and-pencil) multiplication of two n-bit unsigned numbers produces up to n partial products (one per multiplier bit), which are shifted and summed to give a 2n-bit product. Hardware avoids storing all n partial products simultaneously by accumulating them one at a time into a running partial sum.

Fig 3. Sequential binary multiplier: A and Q together hold the running partial product; bit q₀ of Q drives the Add/No-add control.

Procedure: load the multiplier into Q, the multiplicand into M, and clear C and A to 0. Repeat n times: if q₀ = 1, add M to A (storing the sum back in A, with carry-out into C); then shift C, A, Q right by one bit position (regardless of q₀). After n cycles, the high-order half of the 2n-bit product is in A and the low-order half is in Q.

Booth's Algorithm — Signed Multiplication

Part 1 — Arithmetic

Booth's algorithm multiplies two n-bit 2's-complement numbers M (multiplicand) and Q (multiplier), treating both positive and negative operands uniformly, and produces a 2n-bit signed product directly — no separate sign handling is needed.

Its key idea: a run of 1s in the multiplier (say from bit weight 2k down to 2m) can be replaced by 2k+1 − 2m, turning several additions into one addition and one subtraction. Booth generalises this with an extra flip-flop Q₋₁ holding the multiplier bit last shifted out:

q₀q₋₁Operation on A
00none — arithmetic shift right (ASR) of A,Q,Q₋₁
01A ← A + M, then ASR
10A ← A − M, then ASR
11none — ASR only

Fast Multiplication & Bit-Pair Recoding

Part 1 — Arithmetic

Clarifying an ambiguous point in the source The syllabus lists "Fast Multiplication" and "Bit-Pair Recoding of Multipliers" as two separate lines. In the source deck (and standard treatment), fast multiplication in this unit is bit-pair recoding — it is not a distinct third technique — so both syllabus lines are covered by this one section.

Booth's algorithm still requires up to n add/subtract cycles for an n-bit multiplier. Bit-pair recoding, derived directly from Booth recoding, halves this to n/2 cycles by examining the multiplier two bits at a time (plus the bit immediately to the right) and selecting one combined multiple of M per pair: 0, ±1, or ±2 times M.

Fig 5. Each pair of multiplier bits (plus one overlap bit from the pair below) selects a single ±0/±1/±2 multiple of M — halving the number of summands.

Procedure: sign-extend the multiplier by one bit at the MSB, and append an implied 0 to the right of the LSB. Working from LSB to MSB, take overlapping 3-bit windows in steps of 2 and look up the multiple of M from the table above; each selected multiple is shifted left by twice its pair-index and summed.

1.6

Integer Division

Part 1 — Arithmetic

An n-bit positive divisor is loaded into register M, an n-bit positive dividend into register Q, and register A is cleared to 0. After n cycles of shift-and-subtract, the n-bit quotient ends up in Q and the remainder in A. Two variants differ in how they handle a subtraction that goes negative.

Restoring division

Repeat n times: shift A,Q left one bit; subtract M from A. If the result is negative (sign bit of A = 1), set q₀ = 0 and restore A by adding M back; otherwise set q₀ = 1 and keep the subtracted value.

unit deck — Problem 6verified
Given A = 10101 (dividend Q, decimal 21) and B = 00100 (divisor M, decimal 4), perform A/B using restoring division.
Solution — full cycle trace
CycleActionAQ
Init—0000010101

5shift, sub M, keep (q₀=1)0000100101

Quotient Q = 00101 = 5, Remainder A = 00001 = 1. Check: 21 = 4×5 + 1. ✓

Non-restoring division

Non-restoring division avoids the extra restoring addition on a negative step by carrying the negative partial remainder forward and choosing add-or-subtract based on the current sign of A on the next cycle:

  1. Repeat n times: if the sign of A is 0, shift A,Q left and subtract M from A; otherwise shift A,Q left and add M to A.
  2. After the shift+add/subtract, if the sign of A is now 0 set q₀ = 1, else set q₀ = 0.
  3. After the loop, if the sign of A is 1, perform one final restoring addition: A ← A + M.

Floating-Point Numbers — IEEE 754 Single Precision

Part 1 — Arithmetic

IEEE single precision packs a real number into a 32-bit word with three fields: 1 sign bit, an 8-bit biased exponent, and a 23-bit mantissa (fraction). The scale factor spans 2−126 to 2+127 (≈ 10±38).

Fig 8. E' = E + 127 (the biased/excess-127 exponent); the leading "1." of a normalised mantissa is implicit and not stored.

Conversion procedure

  1. Convert the magnitude to binary (integer part and fractional part separately).
  2. Normalise: shift the binary point so exactly one non-zero digit sits to its left, giving the form 1.xxxx × 2e.
  3. Bias the exponent: E' = e + 127, written as an 8-bit unsigned binary number.
  4. The mantissa field stores the 23 bits after the implicit leading 1.
  5. Assemble sign · E' · mantissa into the 32-bit word.
Special values (end codes of E') E'=0, M=0 represents exact 0. E'=255, M=0 represents ±∞ (the result of dividing a normal number by zero). E'=0, M≠0 represents a denormal number (value = M × 2−126, no implicit leading 1). E'=255, M≠0 represents NaN (not a number — e.g. the result of 0/0).

2.1

Boolean Functions & Canonical Forms

Part 2 — Simplification

A Boolean function f(x₁,…,xₙ) maps each of the 2n combinations of n binary inputs to a binary output, using only AND, OR and NOT. Any such function can be written directly from its truth table in two canonical (standard) forms.

Minterms and maxterms

A minterm is an AND (product) term containing every variable exactly once, primed if its value is 0 in that row and unprimed if 1. A maxterm is the dual: an OR (sum) term with every variable once, unprimed if 0 and primed if 1. With n variables there are 2n of each, and every maxterm is the complement of its same-indexed minterm.

X Y ZMintermMaxterm
0 0 0x'y'z' (m₀)x+y+z (M₀)
0 0 1x'y'z (m₁)x+y+z' (M₁)
⋮⋮⋮
1 1 1xyz (m₇)x'+y'+z' (M₇)

A function is written as a sum of minterms (OR together the minterm for every row where f=1) or, in shorthand, F(X,Y,Z) = Σm(1,4,5,6,7). Equivalently it is the product of maxterms for every row where f=0: F(X,Y,Z) = ΠM(0,2,3).

Standard (SOP / POS) forms

  • Sum of Products (SOP): an OR of AND-terms, each term having one or more literals — e.g. F = x + xy' + x'yz. Implemented as a 2-level circuit: AND gates feeding one OR gate.
  • Product of Sums (POS): an AND of OR-terms — e.g. F = x(x+y')(x'+y+z). Implemented as OR gates feeding one AND gate.
Fig 9. Both standard forms give a two-gate-level circuit; input inverters (for primed literals) are not counted as a level.

Complement of a function (De Morgan)

The generalised De Morgan rule: to complement a function, interchange AND and OR, and complement every literal.

F = X'YZ' + X'Y'Z' F' = (X'YZ')' · (X'Y'Z')' complement each product, AND them = (X+Y'+Z) · (X+Y+Z)

2.2

Karnaugh Maps

Part 2 — Simplification

A Karnaugh map (K-map) is a 2-dimensional rearrangement of the truth table in which adjacent cells differ in exactly one variable — row and column headers are ordered in Gray code (00, 01, 11, 10, …) rather than binary counting order, specifically so that this single-variable-difference property holds between every pair of physically neighbouring cells, including wraparound from the last column/row back to the first.

Correcting an error in the source Several 4-variable K-map figures in the source deck mislabel the CD row headers as 00, 01, 01, 01 (a transcription slip repeating "01"). The correct Gray-code sequence — used throughout this guide — is 00, 01, 11, 10. Every K-map below uses the corrected labelling.

Minimisation procedure

  1. Plot a 1 in every cell whose minterm is in the function (for don't-cares, mark X — see §2.3).
  2. Circle groups of adjacent 1s, each group sized as a power of 2 (1, 2, 4, 8, 16 cells) — bigger groups give simpler (fewer-literal) terms.
  3. Every 1 must be covered by at least one group; a 1 may belong to more than one group.
  4. A variable drops out of a group's term if the group spans both its 0 and 1 values; the surviving literals AND together to form that group's product term.
  5. OR all the group terms together for the minimal SOP.
Fig 10. Unsimplified Q = A′BC′D + A′BCD + ABC′D′ + ABC′D + ABCD + ABCD′ + AB′CD + AB′CD′. Three groups of 4 cover all eight 1s: the whole AB=11 column (term AB), the bottom-right 2×2 block (term AC), and the centre 2×2 block (term BD) — note the AC and BD groups reuse shared cells, which is allowed. Minimal SOP: Q = AB + AC + BD.

Prime implicants and essential prime implicants

An implicant is any product term that is a "covering" of one or more minterms of the function. A prime implicant (PI) is an implicant that cannot be combined with another to drop a further literal — i.e. the largest possible group containing that cell. An essential prime implicant (EPI) is a PI that is the only PI covering some particular minterm — it must appear in every minimal SOP, so it is always selected first. Non-essential PIs are only added afterward, if needed, to cover any minterms the EPIs missed.

unit deck — majority functionverified
Minimise M(a,b,c) = Σm(3,5,6,7) — output 1 whenever at least 2 of the 3 inputs are 1.
Solution

Algebraic route: M = a'bc + ab'c + abc' + abc = bc + ac + ab (each pair of adjacent-in-one-variable minterms merges after replicating abc). K-map grouping gives the identical 3 pairs directly. Verified: M = ab + ac + bc.

Don't-Care Conditions & the Variable Entered Map

Part 2 — Simplification

Sometimes a certain input combination can never occur in the application, so it does not matter whether the function is defined as 0 or 1 there. These entries are marked X (or d) in the truth table and K-map. Because we are free to choose either value, an X is included in a group only when doing so makes the group bigger (and hence the term simpler) — otherwise it is left out. This is exactly the "Incomplete Boolean Expressions" case named in the syllabus.

unit deck — BCD prime-number exampleverified
A circuit must output 1 for the prime digits (2,3,5,7) of a BCD input, 0 for the other valid digits (0,1,4,6,8,9), and "don't care" for the unused codes 10–15. Minimise.
Solution

F = Σm(2,3,5,7) + Σd(10,11,12,13,14,15). Grouping the four minterms with the don't-cares (all six are available to extend groups) gives two 4-cell groups:

F = B'C + BD down from the unsimplified 4-term, 4-literal SOP Σm(2,3,5,7)

Without the don't-cares, the same four minterms alone would need a longer expression — the six unused input codes let two of the essential prime implicants absorb neighbours and shrink from 4-literal terms to 2-literal terms.

Variable Entered Map (VEM)

A plain K-map becomes unwieldy beyond 5–6 variables. The Variable Entered Map extends a smaller map's effective capacity by writing an output variable (rather than just 0/1) inside a cell — e.g. a 3-variable function can be drawn on a 2-variable map if the third variable's value is written into the cells instead of a constant.

Fig 12. Row A=0,B=1 gives C (from minterm 5=101); row A=1,B=0 gives C′ (from minterm 2=010 present, 6=110 absent) — read directly off which minterms are in the on-set.

Minimisation procedure for a VEM (X used for don't-care):

  1. Treat the map's own variables normally; obtain a first SOP term by writing every occurrence of the map-entered variable as 0, leaving 0s/1s/don't-cares as they are.
  2. For each map-entered variable in turn: set its own occurrences to 1 and treat its former 1-cells as don't-care; simplify to get an SOP, then multiply that SOP by the variable.
  3. Repeat step 2 for the variable's complement.
  4. OR all the resulting SOP expressions together.
Exam tip VEM is most useful for realising a function on a multiplexer — the map-entered variables become the MUX data inputs, and the map's own variables become the select lines.

Quine–McCluskey Tabulation Method

Part 2 — Simplification

Not in your materials — added for syllabus completeness The syllabus names the Quine–McCluskey method explicitly, but the source deck only defines the term "prime implicant" in passing (crediting W. V. Quine) — it never demonstrates the tabulation algorithm itself. This entire section is written from the standard method, every grouping and chart step verified in code, and cross-checked against a worked problem that appears — with the identical answer — in two independent past exam papers.

K-maps become error-prone and hard to draw beyond 4–5 variables, and they rely on the human eye to spot groupings. The Quine–McCluskey (QM) method finds the same prime implicants algorithmically, by repeatedly combining minterms that differ in exactly one bit — which makes it suitable for programs and for functions with many variables.

Procedure

  1. Write every minterm (and don't-care, if any) in binary, and group them by their number of 1s.
  2. Compare every term in each group only with terms in the next-higher group. If two terms differ in exactly one bit position, combine them into a new term with a dash (-) at that position, and tick off (mark used) both source terms.
  3. Repeat step 2 on the newly formed groups until no further combination is possible.
  4. Any term that was never ticked off during this process is a prime implicant.
  5. Build a prime-implicant chart: rows = prime implicants, columns = the original minterms. Mark an X where a PI covers a minterm.
  6. A column with exactly one X identifies an essential PI — select it, and remove every minterm it covers from the chart.
  7. For any minterms still uncovered, choose the fewest additional PIs (by inspection, or Petrick's method for larger problems) to cover them. OR all selected PIs together for the minimal SOP.

R.1

Quick Revision Sheet

One-page formula and rule dump

Number systems & overflow

  • 2's complement of N (n-bit) = 2n − N = (bit-complement) + 1
  • Range: −2n−1 to +2n−1−1
  • Add: sum bits, discard carry-out
  • Subtract X−Y: X + 2's-complement(Y)
  • Overflow only when adding same-sign operands; detect via carry-into-sign ≠ carry-out-of-sign

Booth's algorithm

  • q₀q₋₁ = 10 → A←A−M; = 01 → A←A+M; = 00/11 → no-op
  • Always finish each cycle with an arithmetic shift right of A,Q,Q₋₁
  • n cycles for n-bit operands; product is 2n bits in A:Q

Bit-pair recoding

  • Sign-extend multiplier by 1 bit; append implied 0 at LSB
  • Read overlapping 3-bit windows in pairs → digit ∈ {0,±1,±2}
  • n/2 summands instead of n

Division

  • Restoring: shift, subtract M; if A<0, restore (A+M) and q₀=0, else keep and q₀=1
  • Non-restoring: shift and add-or-subtract based on current sign of A; set q₀ from new sign; one final restore if A<0 at the end

IEEE 754 single precision

  • 1 sign + 8 exponent (excess-127) + 23 mantissa bits
  • Value = ±1.M × 2^(E′−127); normalise so exactly one leading 1
  • E′=0,M=0 → 0; E′=255,M=0 → ∞; E′=0,M≠0 → denormal; E′=255,M≠0 → NaN

K-maps

  • Headers in Gray code (00,01,11,10) — never binary order
  • Group sizes must be powers of 2; bigger groups → fewer literals
  • Essential PI = sole cover of some minterm; select first, then cover leftovers
  • Don't-cares (X) used only when they enlarge a group

Quine–McCluskey

  • Group minterms by count of 1s; combine only with the next-higher group, one-bit difference
  • Un-ticked terms after all rounds = prime implicants
  • Build PI chart; columns with one X → essential PI; cover remaining columns with fewest extra PIs

Canonical forms

  • Minterm = product of all literals, primed where input bit is 0
  • Maxterm = sum of all literals, primed where input bit is 1; maxterm = complement of same-index minterm
  • F = Σm(on-set) = ΠM(off-set)
  • De Morgan complement: swap AND/OR, complement every literal
