Fundamental Concepts

What the processing unit does with every instruction: fetch it, then execute it as a sequence of simple internal operations. U5a deck pp.1–4, 6

Start here · Reading Control Signals & Memory Notation
  • Gating signals (Xout vs Xin): out copies register X onto the internal bus; in loads from the internal bus into X. For MDR, the extra E (MDRinE, MDRoutE) means the External memory bus.
  • Why Y, Z, Select4, WMFC, End exist: On a single bus only ONE number can travel per clock cycle, so Y holds the ALU's first input while the second travels on the bus, and Z catches the ALU output until the bus is free. Select4 feeds constant 4 to compute PC + 4; WMFC pauses the step counter until memory asserts MFC ("done"); End resets the step counter to T1.
  • Control step notation: Signals listed on the same step run simultaneously in one clock cycle.
  • Powers of 2 for Part 2: 210 = 1K, 220 = 1M, 230 = 1G — so 512K = 29 × 210 = 219 and 128M = 27 × 220 = 227.

The processing unit executes machine-language instructions and coordinates the activities of the other units. To execute a program, the processor fetches one instruction at a time and performs the operation it specifies. Instructions are fetched from successive memory locations until a branch or jump is met. The program counter (PC) keeps track of the address of the next instruction to be fetched; after each fetch it is updated to point to the next instruction. The fetched instruction is placed in the instruction register (IR), where the control circuitry interprets (decodes) it.

Consider a 32-bit computer in which each instruction occupies one word, as in a RISC-style ISA, with byte-addressable memory. To execute an instruction the processor performs three steps:

  1. Fetch the contents of the memory location pointed to by the PC; they are the instruction, so load them into IR: IR ← [[PC]]
  2. Increment the PC to point to the next instruction: PC ← [PC] + 4
  3. Carry out the operation specified by the instruction in IR.

Steps 1–2 form the instruction fetch phase; step 3 is the instruction execution phase. The operation specified by an instruction is carried out by performing one or more of these internal operations, in a specified sequence:

  • Transfer a word of data from one processor register to another, or to the ALU.
  • Fetch the contents of a memory location and load them into a processor register.
  • Perform an arithmetic or logic operation and place the result in a processor register.
  • Store data from a processor register into a memory location.

The processor talks to memory through MAR (memory address register, k bits, so up to 2k addressable locations) and MDR (memory data register, n bits transferred per memory cycle), with control lines Read, Write and MFC (memory function completed). This processor–memory interface is drawn in Unit IV §2.3. The rest of Part 1 shows how these operations are performed by the hardware, each in one clock cycle, and how the control unit sequences them.

Hardware Components

The single-bus datapath used in all the faculty's control sequences: its registers, ALU, multiplexer and the gating signals that connect them to the bus. U5a deck pp.5, 7, 8

In this topic2.1 Single-bus organisation2.2 Register gating2.3 MDR connections2.4 The textbook's multi-stage datapath

2.1 Single-bus organisation of the datapath

Swipe or scroll sideways to read the full diagram.

Fig 1. Single-bus organisation of the datapath (deck p.5). Every register, the ALU's B input and the Z output share one internal bus; MAR and MDR connect it to the memory bus.

In this organisation the ALU and all the registers are interconnected by a single common bus. This internal bus is different from the external bus that connects the processor to memory and I/O.

  • MAR: input from the internal bus, output to the address lines of the memory bus.
  • MDR: two inputs and two outputs. Data may be loaded from either the memory bus or the internal bus, and its contents may be placed on either bus.
  • R0 … Rn−1: general-purpose registers for the programmer. Y, Z and TEMP are temporary registers used only by the processor during execution; the programmer cannot use them.
  • MUX: selects either the output of Y or the constant 4 as the ALU's A input (control signals SelectY / Select4). The constant 4 is used to increment the PC by 4. The B input comes from the bus.
  • ALU: its function is chosen by control lines (Add, Sub, XOR, …, carry-in). Its result goes to Z, which holds it until the bus is free.
  • Instruction decoder and control logic: interpret IR and generate the control signals that select the registers involved and direct the data transfers; the memory control lines connect here.

The registers, the ALU and the interconnecting bus are collectively called the datapath. Because there is one bus, only one data item can be transferred over it in a clock cycle; this is what forces the extra steps in the single-bus control sequences.

2.2 Input and output gating of registers

For each register Ri there are two control signals: Ri,in loads the data on the bus into Ri, and Ri,out places the contents of Ri on the bus. The input and output of the register are connected to the bus through switches controlled by these signals (in practice, tri-state gates). When Ri,in = 1 the data move from the bus into Ri; when Ri,out = 1 they move from Ri onto the bus. Example: to copy R1 into R4, set R1out = 1 and R4in = 1 in the same clock cycle. Y, Z, PC, IR and TEMP are gated the same way (Y has only Yin, because Y feeds the MUX directly).

Swipe or scroll sideways to read the full diagram.

Fig 2. (a) Two switches connect a register to the bus: Ri,in loads it, Ri,out drives the bus. (b) MDR has four controls, two for each bus (deck pp.7–8).

2.3 MDR connections

MDR has four control signals: MDRin and MDRout control its connection to the internal bus, and MDRinE and MDRoutE control its connection to the external memory bus. A memory read ends with MDRinE (data from memory into MDR) and then MDRout (MDR onto the internal bus); a memory write uses MDRin (from the internal bus) and then MDRoutE (onto the memory data lines).

2.4 The textbook's multi-stage datapath (for the syllabus heading)

Not in your materials — added to explain the syllabus wordingThe headings "Hardware Components" and "Instruction Fetch and Execution Steps" come from the newer edition of the reference book, which builds a RISC-style datapath instead of the single bus. Exam questions so far all use the single-bus and three-bus models of the slides; this summary lets you recognise the other model.

In that model, the register file has two output ports and one input port, so two source registers can be read and one destination written in a cycle. Instruction processing is split into five steps, each with its own hardware, separated by inter-stage registers (RA, RB from the register file; RZ at the ALU output; RM holding store data; RY holding the value to write back). An instruction address generator containing the PC and an incrementer updates the PC, and IR feeds the control circuitry.

Instruction Execution: Fetch and Execution Steps

Control sequences on the single-bus datapath: register transfers, an ALU operation, reading and writing memory, complete instructions and branches. U5a deck pp.9–15

In this topic3.1 An ALU operation3.2 Fetching a word from memory3.3 Storing a word3.4 Complete instructions3.5 Branch instructions

A control sequence lists, for each clock cycle (control step), the control signals that are active. The signals named in a step are active for that whole clock cycle; all others are inactive. On a single bus only one item can be transferred per step.

Why can't Add R1, R2, R3 happen in 1 step on a single bus?

A single bus can carry only one operand at a time, so R1 and R2 cannot reach the ALU together and the sum cannot travel back while an input is on the bus. Instead, R1 is parked in Y (step 1), R2 rides the bus to the ALU while the sum is parked in Z (step 2), and Z rides the bus to R3 (step 3).

3.4 Executing a complete instruction

Every instruction begins with the same three fetch steps; step 1 also uses the otherwise idle ALU to compute PC + 4.

Steps 1–3 are the fetch phase; the rest is the execution phase. Step 2 loads Yin alongside PCin because every instruction shares steps 1–3 before decoding—saving PC + 4 in Y costs zero extra cycles and guarantees Y is already loaded if step 4 turns out to be a branch. End resets the control step counter so the next fetch begins. In step 5 of Add (R3), R1, transferring R1 to Y during the memory wait uses an otherwise idle bus cycle and saves one step. (All sequences in this section were run on a simulated single-bus datapath: ADD R1,R2,R3 gives R3 = R1 + R2 in 6 steps; Add (R3),R1 in 7.)

3.5 Branch instructions

A branch replaces the contents of the PC with the branch target address, usually obtained by adding an offset X, given in the instruction, to the PC. The offset is the difference between the target address and the address immediately following the branch, because the PC has already been incremented during the fetch (and step 2 also copied PC + 4 into Y).

Unconditional branch

1. PCout, MARin, Read, Select4, Add, Zin 2. Zout, PCin, Yin, WMFC 3. MDRout, IRin 4. Offset-field-of-IRout, Add, Zin ; Z ← [Y] + offset 5. Zout, PCin, End ; new PC

Conditional branch: Branch < 0

1. PCout, MARin, Read, Select4, Add, Zin 2. Zout, PCin, Yin, WMFC 3. MDRout, IRin 4. Offset-field-of-IRout, Add, Zin, If N = 0 then End ; not taken 5. Zout, PCin, End ; taken

Example (checked): a branch at 1000 with offset 40 gives PC = 1004 + 40 = 1044. For Branch < 0 with N = 0 the sequence ends at step 4 and the PC stays 1004.

Multiple-Bus (Three-Bus) Organisation

Reading two registers and writing a third in one clock cycle; the control sequence and the comparison with a single bus. U5a deck pp.16–17

The single bus allows only one transfer per cycle, so even a register-to-register Add needs three execution steps and temporary registers Y and Z. A three-bus organisation connects the registers and the ALU through three buses: buses A and B carry source operands, bus C carries the result.

Swipe or scroll sideways to read the full diagram.

Fig 4. Three-bus organisation (deck p.16). The register file has two output ports (to buses A and B) and one input port (from bus C).
  • The register file allows the contents of two different registers to be accessed simultaneously and placed on buses A and B, and the data on bus C to be loaded into a third register, in the same clock cycle.
  • Buses A and B feed the ALU's inputs (A through a MUX that can select the constant 4); the result goes on bus C.
  • An incrementer unit increments the PC by 4, so the ALU is not needed for that.
  • The ALU can simply pass one of its two inputs unmodified to bus C: control signals R = A or R = B.
  • No temporary registers (Y, Z) are needed for arithmetic.

Control Signals and Hardwired Control

What the control unit must generate, and how a hardwired control unit produces it from a step counter, two decoders and an encoder. U5a deck pp.18–19

5.1 Control signals

To execute instructions, the processor must generate the control signals of §3 in the proper sequence. They fall into groups: gating signals (Rin, Rout, MDRinE …) that route data, ALU function and MUX select signals (Add, Sub, Select4/SelectY), memory control signals (Read, Write, and WMFC to wait for MFC), and sequencing signals such as End. There are two ways to generate them: hardwired control and micro-programmed control. A hardwired system can operate at high speed, but with little flexibility.

5.2 Hardwired control unit

Swipe or scroll sideways to read the full diagram.

Fig 5. Block diagram of hardwired control (deck p.19). Every control signal is a logic function of the step (T), the instruction (INS) and the external and condition inputs.

Each instruction is a sequence of control steps, and each step is completed in one clock cycle. The hardware has these parts:

  • Control step counter, driven by the clock: keeps track of the step. Each count corresponds to one control step.
  • Step decoder: gives a separate signal line T1, T2, …, Tn for each step; exactly one is active at a time.
  • Instruction decoder: decodes the opcode in IR into a separate line INS1 … INSm for each instruction; exactly one is active.
  • Encoder: a combinational circuit that combines the step lines, the instruction lines, the external inputs (MFC, interrupt requests) and the condition codes (N, Z, …) to generate each individual control signal.
  • Run / End: WMFC holds the counter (Run = 0) until MFC arrives; End resets the counter to T1 so the next instruction is fetched.

5.3 Generating individual signals

Each control signal is the OR of every (step AND instruction) combination in which it appears. From the sequences of §3 (Add (R3),R1 and the unconditional branch BR):

How to write any control-signal equationScan the control-step tables for every (step · instruction) where that signal is 1, and OR them together.
Zin = T1 + T6·ADD + T4·BR + … End = T7·ADD + T5·BR + (T5·N + T4·N̄)·BRN + … BRN = Branch<0

Zin is asserted in T1 for all instructions (the PC + 4 calculation), in T6 for an Add, and in T4 for a branch. End is asserted in T7 for Add, T5 for an unconditional branch, and for Branch < 0 in T5 if N = 1 or in T4 if N = 0 (i.e. N̄ = 1). (These terms were extracted by program from the control-sequence tables.)

Advantages

  • Fast: signals come straight from gates.
  • Suits simple (RISC) instruction sets.
  • Efficient in hardware for a small set.

Disadvantages

  • Inflexible: changing or adding an instruction means redesigning the logic.
  • Complex and error-prone for large instruction sets.
  • Hard to debug.

Micro-programmed Control: Concept and Advantages

Control signals generated by a stored program of control words, the parts of a micro-programmed control unit, and how it compares with hardwired control. U5a deck p.20

In micro-programmed control the control signals are generated by a program, similar to a machine-language program. A control word (CW) is a word whose individual bits represent the various control signals. Each control step of an instruction's control sequence defines a unique combination of 1s and 0s in the CW. The sequence of CWs for one machine instruction is its microroutine, and the individual control words in it are microinstructions. The microroutines for all instructions are stored in a special memory, the control store. To read the control words in sequence, a micro-program counter (µPC) is used.

Operation. When a new instruction is loaded into IR, the starting and branch address generator loads the µPC with the starting address of that instruction's microroutine. The µPC is incremented by the clock, so successive microinstructions are read from the control store; each control word provides the control signals for one step. The generator also loads a new address into the µPC when a microinstruction calls for a branch (for example, on a condition code or an external input such as MFC), and at the end of the microroutine control returns to the fetch microroutine.

Advantages of micro-programmed control
  • Flexible: the control behaviour is changed by rewriting the microprogram, not by redesigning logic; new instructions can be added and bugs fixed.
  • Systematic, regular design that is easy to understand, document and verify, even for very large, complex (CISC) instruction sets.
  • Easier debugging and maintenance; the same hardware can emulate other instruction sets.
  • Lower design cost and time for complex processors.

The price is speed: every step needs a read from the control store, so it is slower than hardwired control. Microinstructions in which each bit is one control signal (as in the table) are horizontal (wide, fast, much parallelism); vertical microinstructions encode groups of signals in fewer bits and decode them, saving control-store space at the cost of speed.

The Memory System: Basic Concepts and the Memory Hierarchy

Address space, the processor–memory connection, speed measures, and why memory is built as a hierarchy. U5b deck pp.2–5, 16

7.1 Basic concepts

The maximum size of the memory that can be used in a computer is set by its addressing scheme. A machine that generates 16-bit addresses can address 216 = 64K locations; 32-bit addresses reach 232 = 4G locations; 64-bit addresses reach 264 = 16E (≈ 16 × 1018). The number of locations is the address space. Data move between the processor and main memory through MAR and MDR: a k-bit MAR addresses 2k locations, and an n-bit MDR transfers n bits per memory cycle. The connection carries address, data and control lines (Read, Write, MFC), as in Unit IV §2.3.

A design goal is a memory that is as large and as fast as possible within a given cost. Two techniques help: cache memory increases the effective speed, and virtual memory increases the effective size. Main memory is semiconductor memory: RAM (random-access, read/write, volatile) for user programs and data, and ROM (non-volatile) for permanent information.

7.2 Measures of memory speed

  • Memory access time: the time between the initiation of an operation and its completion, e.g. between Read and MFC.
  • Memory cycle time: the minimum time between the initiation of two successive, independent memory operations (e.g. two reads). It is usually slightly longer than the access time.
  • Latency: the time to transfer one word of data to or from memory. Bandwidth: the number of bits or bytes that can be transferred in one second, which shows how long a whole block takes. Bandwidth depends on both the rate of transfer and the width of the data bus.

7.3 Memory hierarchy

An ideal memory would be fast, large and cheap, but fast memory costs more per bit. So a computer uses several kinds of memory, organised as a hierarchy: small, fast, expensive memory close to the processor, and large, slow, cheap memory further away. Data are moved between levels in blocks, and the hierarchy works because of locality of reference (§11).

8.1 Internal organisation of a memory chip

Memory cells, each storing one bit, are organised as an array. Each row of cells is one memory word, and all cells of a row connect to a common word line driven by the chip's address decoder. The cells of each column connect by two bit lines to a Sense/Write circuit, which connects to the chip's data input/output lines. In a Read, the Sense/Write circuits sense the cells of the selected word and place the bits on the output lines; in a Write, they receive the input data and store them in the selected word's cells.

8.2 Static RAM (SRAM)

Memories whose circuits retain their state as long as power is applied are static. An SRAM cell is two cross-coupled inverters forming a latch, connected to two bit lines b and b′ by transistors T1 and T2, which act as switches controlled by the word line. When the word line is at ground, T1 and T2 are off and the latch keeps its state: for example X = 1, Y = 0 is maintained, representing a stored 1.

Swipe or scroll sideways to read the full diagram.

Fig 11. (a) An SRAM cell: a latch of two cross-coupled inverters, connected to bit lines b and b′ by T1 and T2. (b) A one-transistor DRAM cell: a capacitor C reached through transistor T (deck 5b pp.9, 13).
  • Read: the word line is activated to close T1 and T2. If the cell holds 1, b is high and b′ is low; for 0 the opposite. b and b′ are always complements. The Sense/Write circuit at the end of the bit lines monitors them and sets its output.
  • Write: the Sense/Write circuit drives b and b′ instead of sensing them: it places the value on b and its complement on b′, then activates the word line. This forces the cell into the new state, which it keeps when the word line is deactivated.
  • CMOS realisation: transistor pairs (T3, T5) and (T4, T6) form the inverters. In state 1, X is held high by T3 and T6 being on while T4 and T5 are off. Current flows only when the cell is accessed, so CMOS SRAM uses very little power.
  • Continuous power is needed: if it is interrupted the contents are lost, so SRAMs are volatile. Access times are a few nanoseconds; SRAMs are used where speed matters, notably cache memories, but their cost per bit is high.

8.3 Dynamic RAM (DRAM)

SRAM cells need several transistors. Cheaper, denser memory uses simpler cells that do not keep their state for long unless accessed frequently: dynamic RAM. A DRAM cell is one capacitor and one transistor. To store information, T is turned on and the appropriate voltage is applied to the bit line, charging the capacitor. When T is turned off the charge remains, but not for long: the capacitor slowly discharges through the transistor's tiny leakage current (picoamperes). So the cell must be read before the charge drops below a threshold, and its contents must be refreshed periodically by restoring the full charge. Reading a cell automatically refreshes it; because the word line is common to a row, reading selects and refreshes a whole row at once.

Asynchronous DRAM example: a 256-Mbit chip organised as 32M × 8.

  • Array layout: the cells form a 16K × 16K array. Each row's 16,384 cells are divided into 2,048 groups of 8 bits (2,048 bytes), so 14 row bits + 11 column bits give a 25-bit address per byte (214 × 211 = 225 = 32M).
  • Why only 14 multiplexed pins: to reduce package pin count, the 14-bit row address and 11-bit column address are multiplexed on 14 shared pins instead of using 25 separate address pins.
  • RAS then CAS sequence: the row address is applied first and latched by a pulse on RAS (row address strobe), which starts reading the entire row and refreshes it at the same time. Shortly after, the column address is applied and latched by CAS (column address strobe) to select the right 8 Sense/Write circuits: on a Read their outputs drive data lines D7–D0, and on a Write the data on D7–D0 overwrite the selected cells.
  • Memory controller role: because the processor issues all 25 address bits simultaneously, a memory controller sits between the processor and the DRAM chips to multiplex the address into row and column parts, generate RAS and CAS, and manage periodic refresh.

8.4 Synchronous DRAM and DDR SDRAM

In the early 1990s, DRAMs whose operation is synchronised with a clock appeared: synchronous DRAMs (SDRAMs). The cell array is the same as in asynchronous DRAM; the clock allows control circuitry on the chip to provide useful features. SDRAMs have built-in refresh circuitry with a refresh counter, so the dynamic nature is almost invisible to the user. Address and data connections can be buffered by registers; a Read loads the whole selected row into the Sense/Write latches, and the selected column's data move to the data register and the output pins. The buffers are useful for transferring large blocks at high speed. Modes of operation are selected by writing to a mode register; for example, burst transfers of different lengths.

Double-data-rate SDRAM (DDR SDRAM) uses the fact that many bits are accessed inside the chip when a row is opened, and transfers data externally on both the rising and falling edges of the clock. The cell array is organised in banks that can be accessed in an interleaved way. Later versions DDR2, DDR3 and DDR4 offer more capacity, lower power and faster clocks: DDR2 and DDR3 run at 400 and 800 MHz, so they transfer data at effective rates of 800 and 1600 MHz.

Read-only Memories

Non-volatile memories and the five types: ROM, PROM, EPROM, EEPROM and flash. U5b deck pp.24–28

SRAM and SDRAM are volatile: they lose their contents when power is turned off. Many applications need memory that keeps its contents without power. For example, when a computer is switched on, the instructions that load the operating system from disk must already be in memory. Such non-volatile memory is read in the same way as volatile memory, but a separate process is needed to write information into it; since normal operation only reads it, it is called read-only memory (ROM).

ROM cell. A logic value 0 is stored if the transistor of the cell is connected to ground at point P; otherwise 1 is stored. The bit line is connected through a resistor to the power supply. To read, the word line turns on the transistor: if it is connected to ground, the bit line is pulled low (0); if not, the bit line stays high (1). The connections are made when the chip is manufactured.

Cache Memories and Mapping Functions

In this topic11.1 Locality of reference11.2 Hits, misses and write policies11.3 Direct mapping11.4 Associative mapping11.5 Set-associative mapping

11.1 Locality of reference

The processor is much faster than main memory, so it spends much of its time waiting while instructions and data are fetched. The speed of main memory cannot be increased beyond a point because of cost and size. A cache memory is an arrangement that makes main memory appear faster than it is. It relies on a property of programs called locality of reference: many instructions in localised areas of a program (loops, nested loops, procedures that call each other) are executed repeatedly during a period of time, while others are accessed rarely.

  • Temporal locality: a recently executed instruction (or accessed data item) is likely to be used again very soon. So keep it in the cache.
  • Spatial locality: instructions and data at addresses close to a recently used one are likely to be used soon. So bring a whole block (several adjacent words) into the cache, not one word.

11.2 Cache operation: hits, misses and write policies

When the processor issues a Read for a word not in the cache, the block of words containing it is transferred from main memory to the cache; later references to words in that block are then found in the cache. Only some blocks of main memory are in the cache at any time; which cache location a block may use is decided by the mapping function. When the cache is full and a new block must come in, a replacement algorithm chooses the block to remove. The existence of the cache is transparent to the processor, which issues Reads and Writes as usual.

CaseWhat happens
Read hitThe data are obtained from the cache.
Write hitWrite-through: the cache and main memory are updated simultaneously. Write-back (copy-back): only the cache is updated and the block is marked with a dirty (modified) bit; main memory is updated when the block is replaced.
Read missThe block containing the word is copied from main memory into the cache, then the word is sent to the processor. Or the word is forwarded as soon as it arrives, without waiting for the whole block: load-through (early restart).
Write missWrite-through: the word is written directly to main memory. Write-back: the block is first brought into the cache, then the word is overwritten in the cache.

Valid bit and cache coherence. Each cache block has a valid bit: 1 if the block holds valid data, cleared to 0 at power-on and set when a block is loaded. Transfers between disk and main memory (for example by DMA, §15) bypass the cache; if such a transfer changes a memory block that also has a copy in the cache, the cached copy's valid bit is cleared. With write-back, the cache may hold newer data (dirty) than memory; if the disk then reads the stale memory copy, or overwrites memory, cache and memory disagree. This is the cache coherence problem; one solution is to force a write-back of dirty blocks before memory is transferred to or from the disk.

Replacement algorithms. In direct mapping there is no choice. In associative and set-associative caches, the usual choice is to replace the least recently used (LRU) block, which follows temporal locality; simpler alternatives are first-in-first-out and random replacement.

The mapping functions below use the deck's (Hamacher's) example: a cache of 128 blocks of 16 words (2K words), a main memory of 64K words (16-bit word addresses), so main memory has 64K / 16 = 4096 blocks. Consecutive addresses refer to consecutive words.

Bookshelf intuition for the three mappings
  • Direct mapping: every main-memory block has exactly one assigned slot (j mod N) — fast lookup, but blocks can collide even when other slots sit empty.
  • Fully associative: a block can go in any slot — zero conflict collisions, but every tag must be searched in parallel.
  • k-way set-associative: a compromise — the cache is split into sets of k slots; a block goes to one assigned set (j mod sets) and can sit in any of its k slots.

11.3 Direct mapping

Block j of main memory maps onto block j modulo 128 of the cache. Blocks 0, 128, 256, … go to cache block 0; blocks 1, 129, 257, … to cache block 1; and so on. The 16-bit address has three fields: a 4-bit word field (16 words per block), a 7-bit block field (which of 128 cache blocks), and a 5-bit tag (4096 / 128 = 32 memory blocks share each cache block, 25 = 32). The tag stored with the cache block says which of them is there. On an access, the block field selects the cache block and its tag is compared with the address's tag: equal means a hit; otherwise it is a miss and the block is loaded and the tag updated.

Direct mapping is easy to implement, but not flexible: since several memory blocks compete for one cache position, contention can arise even when the cache is not full (e.g. a loop that alternates between blocks 0 and 128 misses every time).

11.4 Associative mapping

The most flexible method: a main-memory block can be placed in any cache block. The address has two fields: 4-bit word and 12-bit tag (212 = 4096 identifies the memory block). The tag bits of the address are compared with the tags of all cache blocks to see if the block is present: an associative search, which must be done in parallel to avoid delay. It gives complete freedom of placement and makes efficient use of the cache: a block is ejected only when the cache is full, chosen by a replacement algorithm such as LRU. The cost is complexity: 128 tag comparisons on every access.

11.5 Set-associative mapping

A combination of the two: the cache blocks are grouped into sets, and a memory block may reside in any block of one specific set. This eases the contention of direct mapping, and the associative search is only over one set. With two blocks per set (a 2-way set-associative cache) there are 64 sets: memory blocks 0, 64, 128, …, 4032 map into set 0 and can occupy either of its two blocks. The address has a 4-bit word field, a 6-bit set field (64 sets) and a 6-bit tag; the tag is compared associatively with the tags of the two blocks of the selected set.

12.3 Performance considerations

Two key factors in the success of a computer are performance and cost; the memory hierarchy aims for the speed of the fastest level at the cost of the cheapest. A cache access that succeeds is a hit; the fraction of accesses that hit is the hit rate h, and 1 − h is the miss rate. The extra time needed on a miss to bring the block into the cache is the miss penalty. High hit rates (well over 0.9) are essential. The average (effective) access time is:

TE = h · TC + (1 − h) · TM TC = cache access time, TM = main-memory access time (or miss penalty)

External Devices and Program-Controlled I/O

How devices connect to the bus, how a program polls status flags to move data, and why that wastes processor time. U4 deck p.30 QB2 Q13–17

13.1 External devices and their interfaces

External (peripheral) devices let the computer communicate with the outside world: keyboards, mice, displays, printers, disks, network interfaces, sensors. They differ widely in speed, data format and timing, and nearly all are far slower than the processor. Each device connects to the bus through an I/O interface (device controller) containing:

  • an address decoder that recognises the addresses assigned to the device;
  • data registers (buffers) that hold the data being transferred, e.g. DATAIN, DATAOUT;
  • status registers with flags the processor can test, e.g. SIN, SOUT;
  • control circuitry that coordinates transfers with the bus and the device.

In memory-mapped I/O, the same address space is used for memory and I/O: some addresses refer to device registers, and ordinary instructions (Move, Load, Store) access them, e.g. MoveByte DATAIN, R1. Alternatively, a separate I/O address space with special In/Out instructions can be used.

13.2 Program-controlled I/O

Consider reading characters from a keyboard and echoing them on a display. The processor is much faster than either device, so transfers must be synchronised. The keyboard interface has an 8-bit buffer DATAIN and a status flag SIN (bit 3 of INSTATUS): pressing a key places its ASCII code in DATAIN and sets SIN = 1; reading DATAIN clears SIN to 0. The display interface has a buffer DATAOUT and a flag SOUT (bit 3 of OUTSTATUS): SOUT = 1 when the display is ready to receive a character; writing DATAOUT clears it until the character has been displayed.

This is program-controlled (polled) I/O: the processor repeatedly tests a status flag in a wait loop until the device is ready, and then transfers the data itself.

13.3 Drawbacks of program-controlled I/O

  • Busy waiting wastes processor time. While a slow device gets ready (a person typing a few characters per second), the processor executes millions of useless test-and-branch instructions instead of useful work.
  • The processor is fully occupied by one transfer and cannot overlap computation with I/O.
  • Poor response with many devices: polling them in turn delays the service of each, and an urgent device may wait behind others.
  • Every word passes through the processor, so large block transfers (disk, network) are slow and tie it up.

Two improvements remove these drawbacks: interrupts (§14) let the device tell the processor when it is ready, and direct memory access (§15) moves whole blocks without the processor.

Interrupt Processing and Design Issues

How a device interrupts the processor, what the processor does, and the design issues of enabling, identifying, prioritising and arbitrating interrupts.

This section follows the textbook's chapter on basic input/output (Hamacher). Check your faculty's lectures for the exact list they mean by "design issues".

14.1 What an interrupt is

Instead of the processor waiting in a loop, the device can alert the processor when it is ready by sending a hardware signal, an interrupt, on an interrupt-request (INTR) line. The processor can do other useful work meanwhile. When the request arrives, the processor suspends the current program, executes an interrupt-service routine (ISR) that services the device, and then resumes the interrupted program.

Swipe or scroll sideways to read the full diagram.

Fig 16. Transfer of control through an interrupt-service routine. The request arrives during instruction i; after the ISR, execution resumes at i + 1.

An ISR resembles a subroutine, but with one key difference: it usually has nothing to do with the program being interrupted, which can be anywhere when the request arrives. So everything the ISR changes that could affect the interrupted program (the PC, the condition-code/status register, and any registers it uses) must be saved before, and restored after, the ISR.

14.2 Interrupt processing, step by step

  1. The device raises an interrupt request.
  2. The processor completes the current instruction (i), then checks for pending requests.
  3. If interrupts are enabled, it saves the PC (address i + 1) and the processor status register (PS), typically on the stack, and disables further interrupts.
  4. It informs the device that the request is recognised, by an interrupt-acknowledge (INTA) signal or by the ISR accessing the device's registers, so the device removes its request.
  5. It loads the PC with the address of the ISR and executes it; the ISR saves the registers it uses, services the device and restores them.
  6. A Return-from-interrupt instruction restores PS and PC, re-enabling interrupts, and the interrupted program continues at i + 1.

The delay between the request and the start of the ISR is the interrupt latency. Saving many registers automatically increases it, so processors often save only the PC and PS automatically and leave the rest to the ISR.

14.3 Enabling and disabling interrupts

The programmer must be able to control when interrupts are accepted, for example to prevent the same request from interrupting its own ISR repeatedly, or to protect a critical section. Two levels of control are used:

  • Processor level: an interrupt-enable (IE) bit in the processor status register. When IE = 0, requests are ignored (held pending). The processor clears IE automatically on accepting an interrupt; Return-from-interrupt restores it. Alternatively, the processor may accept a request only on its leading edge (edge-triggered), so one request is seen once.
  • Device level: each interface has an interrupt-enable bit in its control register (e.g. KIE for the keyboard, DIE for the display). Only when it is set may the device raise a request, so the program chooses which devices may interrupt.

14.4 Design issues when many devices can interrupt

With several devices, each able to interrupt at any time, the design must answer four questions:

  1. How does the processor identify the requesting device?
    • Polling: the ISR reads each device's status register in turn and services the first whose IRQ bit is set. Simple hardware, but wastes time checking idle devices (up to n devices).
    • Vectored interrupts: the requesting device sends an identification code (an interrupt vector); the processor looks up that device's ISR starting address in an interrupt-vector table in memory. Faster, and each device can have its own ISR.
  2. Can an ISR itself be interrupted (interrupt nesting)? Devices are assigned priority levels. The processor's current priority is held in PS; while an ISR for a device runs, the processor runs at that device's priority and accepts only requests of higher priority. Instructions that change priority are privileged (allowed only in supervisor mode).
  3. What if several requests arrive simultaneously (priority arbitration)?
    • Separate request/acknowledge lines: each priority level has its own INTR/INTA pair wired to a hardware priority-arbitration circuit.
    • Daisy chain: all n devices share one INTR line, while INTA passes serially from device to device (Fig 17). The first device with a pending request blocks INTA from propagating further and puts its vector on the bus — so the device electrically closest to the processor has the highest priority.
    • Priority groups: combines both approaches by placing a daisy chain within each priority level.
  4. How are requests controlled? By the enable bits at processor level (IE in PS) and device level (e.g. KIE, DIE), as in §14.3.

14.5 Exceptions

The interrupt mechanism is also used for events other than I/O requests. Any event that causes an interruption is called an exception:

  • Recovery from errors: illegal opcode, divide by zero, arithmetic overflow, memory errors. The processor interrupts the program and runs an exception-service routine (which may terminate the program).
  • Debugging: trace mode raises an exception after every instruction (single-stepping); breakpoints stop the program at chosen points.
  • Privilege exceptions: an attempt to execute a privileged instruction in user mode raises an exception, protecting the operating system.
  • The operating system also uses timer interrupts to switch between programs (multitasking).

Direct Memory Access

Moving blocks of data between a device and memory without the processor handling each word.

Not in your materials — added for syllabus completenessThe decks only name DMA as an improvement on programmed I/O (Unit 4 deck p.30). This section follows the textbook's treatment of DMA at the depth the syllabus line "Direct Memory Access Function" suggests.

With interrupts, the processor still executes instructions to move every word, saving and restoring state each time. For large blocks (disk, network) this overhead is too high. Direct memory access (DMA) transfers a block of data directly between an I/O device and main memory, without continuous involvement of the processor. The transfer is done by a control circuit in the device interface, the DMA controller.

15.1 The DMA controller's function

For each word, the DMA controller performs the functions the processor would otherwise perform: it supplies the memory address and bus control signals, and keeps track of how many words remain. One complete DMA block transfer proceeds in four steps:

  1. Setup: the processor writes the starting address of the memory block, the word count (number of words), and the direction (R/W: Read or Write) into the DMA controller's registers and starts the transfer. The OS normally puts the requesting program into a blocked state.
  2. Direct transfer: the DMA controller requests bus mastership and moves words directly between the device and main memory, incrementing the address and decrementing the word count after each word.
  3. Concurrent CPU work: while the DMA controller moves the block, the processor executes other programs without handling individual words.
  4. Completion interrupt: when the word count hits 0, the DMA controller sets its Done flag and raises an interrupt (if IE = 1) to notify the processor that the block transfer is complete.

Fig 18. Use of DMA controllers in a computer system (after Hamacher), and the registers of a DMA controller.

15.2 Registers and operation

A DMA controller has a starting-address register, a word-count register and a status and control register. Typical status/control bits: R/W (1 = read from memory to the device, 0 = write into memory), Done (set when the block is complete), IE (interrupt enable: raise an interrupt when Done) and IRQ (set when the controller has requested an interrupt). A disk controller may have several DMA channels, each with its own set of registers.

  • Cycle stealing: memory accesses by the processor and DMA controllers are interwoven. The controller "steals" individual memory cycles from the processor, which is slowed only slightly; requests from DMA devices usually get higher priority than processor accesses.
  • Block (burst) mode: the controller is given exclusive access to memory to transfer a whole block without interruption, for fast devices.
  • Bus arbitration: the device allowed to start transfers on the bus at a given time is the bus master. When a DMA controller needs the bus it requests mastership; an arbiter (centralised, often in the processor, or distributed among the devices) grants it, and mastership returns afterwards.

Answer
  1. Draw Fig 5. In hardwired control, the control signals are generated by combinational logic. Each instruction is a sequence of steps, one per clock cycle.
