Half & Full Adder

The two single-bit combinational blocks every wider adder — ripple, CLA, or decimal — is ultimately built from.

Half adder

A half adder adds two single bits Ai and Bi, producing a Sum and a Carry. It is called "half" because it has no provision for an incoming carry from a previous stage — it can only be the first (least-significant) stage of a wider adder.

A full adder extends the half adder with a third input, the incoming carry Ci, so that full adders can be chained to add operands wider than one bit. It has three inputs (A, B, Ci) and two outputs (Sum, Carry-out Co).

1.2

4-bit Ripple (Parallel) Adder & Its Delay

Chaining full adders to add wide operands — and why the carry chain makes this slow.

A parallel adder computes the sum of two multi-bit binary numbers by cascading full adders, one per bit position, laid out right (least significant) to left (most significant). The carry-out of each stage feeds the carry-in of the next — this is why it is also called a ripple-carry adder: the carry "ripples" through the chain.

Fig 3. 4-bit ripple-carry adder — four full adders chained; the carry-out (Co) of each stage is the carry-in (Ci) of the next, more-significant stage.

Delay analysis — why ripple adders don't scale

Each full-adder stage's carry-out depends on its own carry-in, so the carry-out of a single stage takes 2 gate delays to settle (one AND/OR level after the previous carry arrives). For an N-bit ripple adder, the final (most significant) carry — and hence the final sum bit — is only valid after every stage downstream of it has rippled through:

Total time for N-bit ripple adder = N × 2 units of time For N = 16: 16 × 2 = 32 units of time

This is the motivation for the Carry Look-Ahead Adder: computing every carry directly from the operand bits instead of waiting for it to ripple through every preceding stage.

1.3

4-bit Adder/Subtractor

One circuit, two jobs: the same 4-bit adder does subtraction too, controlled by a single line through XOR gates.

An XOR gate is a controlled inverter: with one input tied to a control signal M and the other to a data bit X, the output is X unchanged when M=0, and X′ (inverted) when M=1. Wiring an XOR gate in front of every B-input bit, with M also driving Cin, turns a plain 4-bit adder into an adder/subtractor:

  • M = 0 (ADD/SUB̄ = 0): each Bi passes through unchanged, Cin = 0 → circuit computes A + B.
  • M = 1: each Bi is inverted (B′) and Cin = 1 is added in → circuit computes A + B′ + 1 = A + (2's complement of B) = A − B.
Fig 4. 4-bit adder/subtractor — M, B3…B0 and A3…A0 are vertical rails. Each XOR combines M with one Bi; its output feeds the adder's Bi pin. Ai goes straight to the adder, and M also drives Cin: M=0 adds, M=1 subtracts (2's complement).

Full Adder via Multiplexer / Decoder

The same full-adder truth table, realised with universal combinational building blocks instead of discrete gates.

Not in your materials — added for syllabus completeness unit 2a.pdf only builds the full adder from discrete gates (§1.1). Via 4:1 multiplexer

Take A and B as the two select lines of a 4:1 MUX, and wire Ci (or its complement, or a constant) into each of the four data inputs so that the MUX output reproduces S — and a second MUX, wired identically but on different data lines, reproduces Co. Via decoder

Reading the minterms where S = 1 and where Co = 1 off the truth table (§1.1) and OR-ing the corresponding decoder outputs realises both functions directly in sum-of-minterms form:

S = Σm(1, 2, 4, 7) — OR the decoder outputs D1, D2, D4, D7 Co = Σm(3, 5, 6, 7) — OR the decoder outputs D3, D5, D6, D7
1.5

Application of Adders: BCD ⇄ Excess-3 Converter

The adder/subtractor of §1.3, reused with one operand hard-wired to a constant — a 4-bit adder becomes a code converter.

BCD (8421 code) represents each decimal digit 0–9 directly in 4-bit binary. Excess-3 is an unweighted code obtained by adding 3 (0011) to the BCD value of each digit — e.g. digit 5: BCD 0101 + 0011 = Excess-3 1000. Converting back subtracts 3.

Reusing exactly the adder/subtractor structure from §1.3, but with the "B" operand hard-wired to the constant 0011 instead of a second variable number:

  • Cin = 0 (adder mode): B-input 0011 passes through the XOR gates unchanged → the circuit computes BCD + 3 = Excess-3.
  • Cin = 1 (subtractor mode): B-input 0011 is inverted by the XOR gates and Cin=1 is added → the circuit computes Excess-3 + (2's complement of 3) = Excess-3 − 3 = BCD.
Fig 6. BCD ⇄ Excess-3 converter — the B-side of Fig 4 is hard-wired to the constant 0011 (the XOR gates see 0, 0, 1, 1) and Cin selects the direction: Cin=0 adds 3, Cin=1 subtracts 3.
worked example — digit 5, verifiedverified
Convert decimal digit 5 from BCD to Excess-3 and back, using the circuit above.
Answer
  1. BCD 5 = 0101. Cin=0: add constant 0011 → 0101 + 0011 = 1000 = Excess-3 code for 5. ✓ (matches the standard Excess-3 table)
  2. Excess-3 1000, convert back: Cin=1 → B is inverted to 1100, plus Cin=1 carry-in → 1000 + 1100 + 1 = 1 0101, discard the overflow carry out of the 4-bit adder → 0101 = BCD 5. ✓

1.6

Carry Look-Ahead Adder (CLA)

Computing every carry directly from the operand bits, instead of waiting for it to ripple through every preceding stage.

Starting from the full-adder carry-out expression and expanding it:

Ci+1 = XiYi + XiCi + YiCi = XiYi + Ci(Xi + Yi)

Define, for each bit position i:

Gi = XiYi (carry generate — this stage produces a carry regardless of Ci) Pi = Xi + Yi (carry propagate — this stage passes an incoming carry through) so  Ci+1 = Gi + PiCi
Clarifying a notational point This source defines Pi = Xi + Yi (OR). Some textbooks instead use Pi = Xi ⊕ Yi (XOR). Both definitions give the same carry recurrence Ci+1 = Gi + PiCi (when Gi=1 the PiCi term makes no difference). They are not interchangeable for the sum: Si = Pi ⊕ Ci holds only for the XOR definition. With the OR definition used here, write Si = Xi ⊕ Yi ⊕ Ci (e.g. X=Y=1, C=0: OR-P gives P⊕C = 1, but the true sum bit is 0).

Substituting each Ci recursively expresses every carry as a two-level function of only the generate/propagate signals and the initial carry-in C0 — no waiting for any intermediate carry to ripple in:

C1 = G0 + P0·C0 C2 = G1 + P1·C1 = G1 + P1G0 + P1P0C0 C3 = G2 + P2·C2 = G2 + P2G1 + P2P1G0 + P2P1P0C0 C4 = G3 + P3·C3 = G3 + P3G2 + P3P2G1 + P3P2P1G0 + P3P2P1P0C0
Verified Brute-forced over all 512 combinations of (X3:0, Y3:0, C0) in code — these CLA carry expressions reproduce the ripple-carry chain exactly, with zero mismatches.
Fig 7. 4-bit CLA adder — each bit block forms Gi and Pi and sends them down; the look-ahead network returns every carry C1…C4 in parallel (2 gate levels), and each bit block then forms Si = Xi⊕Yi⊕Ci.

Propagation delay

Each bit block forms Gi, Pi and Xi⊕Yi in parallel (1 gate level), the CLA network needs 2 gate levels of AND-OR logic to produce any Ci, and the final sum needs 1 more XOR level (Si = (Xi⊕Yi) ⊕ Ci):

Total CLA delay = 1 (Gi, Pi, Xi⊕Yi) + 2 (Ci generation) + 1 (Si = (Xi⊕Yi)⊕Ci) = 4 units of time — independent of the number of bits, vs. N×2 for a ripple adder

For a 4-bit adder this is a clear win (4 units vs. 4×2=8 for ripple), but a single CLA network scales badly: the AND gates computing C4 need 5 inputs, and a 16-bit single-level CLA network would need gates with far too many inputs/fan-in to build practically — which motivates cascading smaller CLA blocks instead of building one giant one.

1.7

Cascading CLA Adders

Building wide fast adders out of 4-bit CLA blocks, and the (optional) block-level lookahead generator that goes one step further.

Cascade connection of 4-bit CLA adders

To add N bits (N divisible by 4), chain ⌈N/4⌉ complete 4-bit CLA blocks, exactly like cascading full adders for a ripple adder — except each block internally computes its 4 carries in parallel. The carry only ripples between blocks, not within one.

Fig 8. Cascade connection of 4-bit CLA adders (12-bit example) — the carry ripples only between the three 4-bit blocks, each of which resolves its own carries internally in 2 gate levels.

Timing: a carry generated in the least-significant block needs 1 level to be generated, 2 levels to propagate to the end of its own block, then 2 more levels for each of the remaining (n/4)−1 blocks it must ripple through, and a final 1 level to produce the last sum bit:

Total time = (1 + 2) + 2[(n/4) − 1] + 1 = 2 + (n/2) levels of logic For n = 16: 2 + (16/2) = 10 units of time
Method (16-bit adder)Time (units)
Ripple-carry adder16 × 2 = 32
Cascaded 4-bit CLA blocks (ripple between blocks)2 + 16/2 = 10

Carry lookahead generator (block-level G, P)

Clarifying the source's own scope note unit 2a.pdf labels this content "Extra Info – Not in syllabus." It is included here anyway because qb1.pdf Q18 directly asks to "explain the working of the carry lookahead generator" — so it is worth knowing even though the source deck itself flags it as beyond the core syllabus.

A separate small circuit — the same first three stages of a CLA network, plus two extra gates — produces a block generate signal G and block propagate signal P for an entire 4-bit group, letting that group be treated as a single generate/propagate pair one level higher up:

G = g3 + p3g2 + p3p2g1 + p3p2p1g0 P = p3p2p1p0
Fig 9. Two-level look-ahead (16-bit) — each 4-bit CLA block outputs a block generate Gk and propagate Pk; the 2nd-level logic returns C4, C8, C12, C16 directly, with no ripple between blocks. C4, C8, C12 are fed back as the carry-ins of the next block.

Feeding four such generators' G/P signals into one more level of lookahead logic gives a genuine two-level-lookahead 16-bit adder (rather than rippling between the four 4-bit blocks), bringing the delay back down toward the CLA ideal — this is the standard textbook figure for a fast 16-bit adder built from four 4-bit CLA generator ICs.

1.8

Decimal (BCD) Adder

A plain 4-bit binary adder gets the wrong answer when adding two BCD digits — here's exactly when, and the correction network that fixes it.

Two decimal digits (0–9), each held in 4-bit BCD, plus an input carry, are first added using an ordinary 4-bit binary adder. The problem: this raw binary sum is not always a valid BCD digit.

worked examples — verified in codeverified
Add the BCD pairs 5+4, 5+6, and 8+9, and show where the raw binary sum goes wrong.
Answer
Decimal sumRaw binary sum (K P3P2P1P0)Valid BCD?
5 + 4 = 90 1001Yes — 1001 is 0–9. No correction needed.
5 + 6 = 110 1011No — 1011 (=11) is not a valid single BCD digit.
8 + 9 = 171 0001No — carry K=1 was produced, but digit 0001 alone reads as "1", not "17".

Adding 6 (0110) as a correction fixes both wrong cases:

5 + 6: raw 1011 + 0110 = 1 0001 → carry 1, digit 0001 → reads as "1 1" = 11 ✓ 8 + 9: raw 1 0001 (K=1) + 0110 = 1 0111 → carry 1, digit 0111 → reads as "1 7" = 17 ✓

When is the +6 correction needed?

Comparing the raw binary sum against the required BCD sum across all 20 possible decade sums (0–19) shows the correction is needed in exactly two cases:

  1. The 4-bit result alone is an invalid BCD code (decimal sums 10–15, binary 1010–1111, with K=0).
  2. The addition already produced a carry (decimal sums 16–19, K=1) — regardless of what P3P2P1P0 is.

Detecting case 1 from a K-map over P3P2P1P0 (grouping minterms 1010,1011,1100,1101,1110,1111) gives:

ADD_6 = P3P2 + P3P1 — detects case 1 ADD_6 = K + P3P2 + P3P1 — including the carry K, detects both cases
Verified Brute-forced this correction logic in code across every valid (digit, digit, carry-in) combination from 0+0 to 9+9+1 — the corrected result always matches the true decimal sum, both for the units digit and the carry-out.
Fig 10. Single-decade BCD adder — adder 1 forms the raw binary sum S and carry K; the gates S3S2 and S3S1 and the OR produce ADD6 = K + S3S2 + S3S1 (= Cout); adder 2 adds 0110 when ADD6 = 1. (The sum bits S3…S0 here are the P3…P0 of the text above.)

Cascading several single-decade BCD adders (carry-out of one decade → carry-in of the next), exactly like cascading full adders, adds multi-digit BCD numbers.

Half & Full Subtractor

The subtraction counterparts of the half and full adder — borrow instead of carry. (From the handwritten notes; not in unit 2a.pdf.)

Half subtractor

A half subtractor subtracts one bit from another: A is the minuend and B the subtrahend. It produces a Difference D and a Borrow Bo (the borrow taken from the next higher bit when A < B). Like the half adder it has no input for a borrow coming from a lower stage, so it can only serve as the least-significant stage.

ABD (difference)Bo (borrow)

D = A′B + AB′ = A ⊕ B — K-map: two diagonal 1s, cannot be grouped → XOR Bo = A′B — compare with half adder: Carry = AB

Notice the only difference from the half adder is the single inverter on A in the borrow term: the Sum/Difference output is the same XOR in both circuits.

Full subtractor

A full subtractor has three inputs — minuend A, subtrahend B and the borrow-in Bin that the previous (less-significant) stage generated — and two outputs, D and Bout. It computes A − B − Bin. NAND-Gate Adders & the IC 7483

Building the half and full adder from NAND gates only, and the 4-bit adder IC the lab experiments use. (From the handwritten notes and lab manual.)

Why NAND? — universal gates

NAND (and NOR) are universal gates: any Boolean function can be built using only NAND gates. In practice this matters because a single IC type (e.g. 7400, four 2-input NANDs) is enough to wire a whole circuit. The two identities used throughout are De Morgan — (XY)′ = X′ + Y′ and (X+Y)′ = X′·Y′ — and the fact that a NAND with both inputs tied together is an inverter.

Half adder using NAND gates

Let N1 = (AB)′. Feed N1 to two more NANDs together with A and with B, and combine those two outputs in a final NAND:

N1 = (AB)′ N2 = (A·N1)′ , N3 = (B·N1)′ Sum = (N2·N3)′ = N2′ + N3′ = A·(AB)′ + B·(AB)′ = A·(A′+B′) + B·(A′+B′) = AB′ + A′B = A ⊕ B Carry = N1′ = ((AB)′)′ = AB — N5: a NAND with both inputs tied = inverter

Five NAND gates are needed (N1, N2, N3, N4 = the Sum NAND, N5 = the carry inverter). Verified exhaustively in code over all four input pairs.

Fig 10c. Half adder with five NAND gates. N1 = (AB)′ is shared: it feeds N2, N3 and the carry inverter N5; N4 = NAND(N2, N3) is the Sum.

Full adder using NAND gates

Build it as two NAND half adders in series. The first produces p = A⊕B; the second adds p and Cin to give Sum = p ⊕ Cin. For the carry, no second "carry inverter + OR" is needed: the two NANDs that already exist, N1 = (AB)′ and N5 = (p·Cin)′, are combined directly:

Cout = ( N1 · N5 )′ = N1′ + N5′ = AB + p·Cin = AB + Cin(A⊕B)

Total: 9 NAND gates (4 + 4 for the two half-adder cores, +1 for Cout); verified for all 8 input combinations.

2.2

N-bit Iterative Comparator

Cascading 1-bit comparators from LSB to MSB — the comparator analogue of a ripple-carry adder.

An N-bit comparator is built as a cascade of identical 1-bit-comparator subnetworks, processed right (LSB) to left (MSB) — the same architectural idea as the parallel adder. Each stage carries forward three flags summarising the relative magnitude of all bits compared so far:

  • Gi = 1 means the bits compared so far show A > B.
  • Ei = 1 means the bits compared so far show A = B.
  • Li = 1 means the bits compared so far show A < B.

Each 1-bit-comparator stage is therefore a 5-input, 3-output block: it takes Ai, Bi, and the incoming Gi, Ei, Li from the previous (less-significant) stage, and produces Gi+1, Ei+1, Li+1.

Recursive rules

  • If Ai=0, Bi=1 → this bit alone decides: Li+1=1.
  • If Ai=1, Bi=0 → this bit alone decides: Gi+1=1.
  • If Ai=Bi → this bit is a tie, so the incoming flag simply carries forward: Gi+1=Gi, Ei+1=Ei, Li+1=Li.
Gi+1 = AiBi′ + AiGi + Bi′Gi Ei+1 = Ai′Bi′Ei + AiBiEi Li+1 = Ai′Bi + BiLi + Ai′Li

At the LSB (first) stage, since there is no previous bit, the incoming flags are seeded to reflect "no comparison yet, so far equal": G0=0, E0=1, L0=0. After the MSB stage, the final Gn, En, Ln directly give A>B, A=B, A<B for the whole N-bit numbers.

Fig 12. N-bit iterative comparator — 1-bit comparator stages chained LSB → MSB; each stage takes the running G/E/L flags plus Ai, Bi and passes updated flags on. The last stage's outputs are the result.

2-bit Magnitude Comparator (Direct Design)

Instead of cascading 1-bit stages, a small comparator can also be designed directly from its full truth table — worth knowing for exactly this reason: it's a different design method, examined separately from the iterative version.

Compare two 2-bit numbers A = A1A0 and B = B1B0. With 4 input bits there are 16 rows in the truth table; K-maps over those 16 rows (one map per output) give the minimal SOP directly:

A>B = A1·B1′ + A0·B1′·B0′ + A1·A0·B0′ A=B = (A1'A0'B1'B0') + (A1'A0B1'B0) + (A1A0B1B0) + (A1A0'B1B0') = (A0 XNOR B0) · (A1 XNOR B1) A<B = A1′·B1 + A0′·B1·B0 + A1′·A0′·B0
Verified Brute-forced these three minimal-SOP expressions against a direct value-comparison (A<B, A=B, A>B computed from A=2A1+A0, B=2B1+B0) over all 16 input combinations in code — zero mismatches, confirming the expressions are correct as well as minimal.

Notice the neat form of the A=B expression: two bits are equal exactly when each corresponding pair is equal, i.e. an XNOR per bit-position, ANDed together. This generalises directly — for any width, A=B is simply the AND of a per-bit XNOR, which is exactly the Ei+1 "carry the equality forward" idea from the iterative comparator in §2.2.

Decoders

n inputs → 2n one-hot outputs: the minterm generator, its enable, and how to build bigger decoders from smaller ones.

Definition and idea

A decoder is a combinational circuit with n input lines and up to 2n output lines that converts an n-bit binary code into a "one-hot" output: for each input combination exactly one output line goes active (the one whose number equals the binary input) and all others stay inactive. Each output is therefore one minterm of the n inputs — a decoder is a "minterm generator". Most decoders also have an enable input E: with E = 1 the decoder works normally; with E = 0 all outputs are inactive regardless of the data inputs. Enable inputs are what allow decoders to be cascaded to make larger ones, and what lets a decoder behave as a demultiplexer (§3.4).

Definition and idea

A multiplexer (MUX) is a combinational circuit that selects one of several data inputs and forwards it to a single output; the choice is made by the select lines. It acts as a digital switch or data selector. A multiplexer with 2n data inputs has n select lines and one output — written 2n:1. So a 4:1 MUX has 2 select lines, an 8:1 has 3 and a 16:1 has 4. MUX as a universal logic element

Since Y is a sum of data·minterm products, a 2n:1 MUX can realise any n-variable function: feed the variables to the select lines and tie each data input to 0 or 1 according to the truth table. A cleverer scheme (§3.5) uses only n−1 select lines and puts the last variable (or its complement) on the data lines.

Demultiplexers

The reverse of a multiplexer — one input routed to one of many outputs — and its identity with the decoder.

Definition and idea

A demultiplexer (DEMUX) is the reverse of a multiplexer: it has one data input and 2m outputs; the m select lines decide which single output receives the input data, while all the other outputs stay 0. It is also called a data distributor. A 1:4 DEMUX has 2 select lines and 4 = 22 outputs. Together, a MUX at the transmitting end and a DEMUX at the receiving end let several signals share one wire (time-division multiplexing).

Decoder ↔ demultiplexer (qb1 Q24)

Compare the DEMUX equations with the decoder equations: Yi = E·I·mi(S) versus Yi = E·mi(A, B). They are identical if the DEMUX's data input I is treated as the decoder's enable. So a decoder becomes a demultiplexer by using its enable pin as the data input and its address inputs as the select lines — when E (=I) is 1 the addressed output goes 1, and when E is 0 all outputs are 0, so the addressed output follows the data. That is why the 74139 can be used as a dual 1:4 DEMUX (its active-low enable acts as the data input, as the lab manual states). Conversely, a DEMUX with its data input held at 1 is a decoder.

Function Realisation with MUX & Decoder

Using a multiplexer or a decoder as a universal logic block — the methods, and every worked question from the question bank and papers.

Realising a function with a multiplexer

Method A — direct (2n:1 MUX for n variables). Connect the n variables to the select lines (MSB to Sn−1). Tie data input Dk to 1 if minterm k is in the function, else 0. No gates are needed, but the MUX is large.

Method B — variable-entered (one fewer select line). Use a 2n−1:1 MUX. The first n−1 variables go to the selects, and the last variable (call it z) is "entered" on the data lines. Pair the two truth-table rows that share the same select combination (z = 0 and z = 1) and set the data input by this table:

f(z = 0)f(z = 1)Data input
000
111
01z
10z′

This is the "tabular (implementation-table) method" the lab manual uses in Experiment 2. Equivalently: list the minterms in two columns, circle those present, and read off 0/1/z/z′ for each column pair.

Method C — two fewer select lines. A 4:1 MUX can realise a 4-variable function with two variables on the selects; each data input is then a function of the remaining two variables (0, 1, a literal, or a small gate output), so a few extra gates are needed.

Realising a function with a decoder

A decoder produces every minterm, so f = Σm(…) is the OR of the corresponding outputs. With active-high outputs use an OR gate; with active-low outputs use a NAND gate (De Morgan: NAND of the active-low lines = OR of the minterms). For a function given as a product of maxterms, f = ΠM(i, j, …) = Σ of the other minterms, so OR (or NAND) the outputs not listed — or, with active-low outputs, simply AND the listed ones. To save gate inputs choose whichever of f or f′ has fewer minterms and add an inverter (NOR instead of OR) if f′ is used.

Experiment 1 — Excess-3 Converter & Adder/Subtractor (IC 7483)

BCD ⇄ Excess-3 with one 4-bit adder and XOR gates, plus the add/subtract exercises.

Aim, components, theory

Aim: to design an Excess-3 ⇄ BCD code converter using the 4-bit parallel adder IC 7483 (and XOR gates 7486) and to use the same adder as an adder/subtractor. Components: IC 7483 ×1, IC 7486 (quad XOR) ×1, digital trainer kit and ~20 patch cords.

Theory. A code converter makes two systems that use different binary codes for the same information compatible. BCD is the weighted 8-4-2-1 code for the decimal digits 0–9 (13710 = 0001 0011 0111). Excess-3 is an unweighted code obtained by adding 0011 to the BCD of each digit. Both use four bits, so the converter has inputs B3B2B1B0 and outputs E3E2E1E0. A parallel adder adds two 4-bit numbers at once; it becomes a subtractor by feeding it the 2's complement of the second operand (XOR gates give the 1's complement, and Cin = 1 adds the 1).

5.1

The Basic Bistable Element

Memory from feedback: two cross-coupled NOT gates, stable and metastable states.

All the logic studied so far was combinational: each output depends only on the inputs present at that instant, so a single Boolean expression describes it. A sequential network is different — its outputs depend on the present inputs and on the past history of inputs. That history has to be remembered inside the network, and the remembered information is called its internal state (or simply the state). Sequential networks therefore have memory, and every one of them needs feedback.

Sequential networks are of two kinds. In a synchronous network the behaviour is decided by the signal values only at discrete instants fixed by a master clock; the clock pulses effectively sample the inputs. In an asynchronous network a change of an input signal affects the network immediately. The basic memory element of both is the flip-flop, and the simplest circuit that can hold a bit is the basic bistable element.

The basic bistable element

The basic bistable element is two NOT gates connected in a loop: the output of the first gate is the input of the second, and the output of the second is the input of the first (Fig 30). It has two outputs, Q and Q, which are always complementary.

Fig 30. Basic bistable element: two cross-coupled NOT gates and its two stable states.

Why it is bistable. Suppose Q = 0. The lower NOT gate then gives Q = 1, and the upper NOT gate, whose input is Q, gives Q = NOT 1 = 0 — exactly the value assumed, so the loop is self-consistent and stays that way. The same argument with Q = 1, Q = 0 is also self-consistent. The circuit therefore has two stable conditions and will stay in whichever one it was in for as long as power is applied. This is how one bit is stored.

  • When Q = 1 the element is said to store a 1 (it is in the 1-state, or set). When Q = 0 it stores a 0 (the 0-state, or reset).
  • Q is the normal output and the state of the element is the value at Q; Q is the complementary output.
  • Storing a 1 is called setting (or presetting); storing a 0 is resetting (or clearing).

Metastable state. There is a third equilibrium: both outputs sitting about halfway between logic 0 and logic 1. This is not a valid logic level. It is unstable — a small disturbance such as circuit noise pushes the element into one of the two stable states — but the time it can linger in the metastable state is unpredictable. For that reason the metastable state is to be avoided, and later sections place timing restrictions (minimum pulse width, setup and hold time) on flip-flop inputs precisely to keep out of it.

From bistable element to flip-flop

The bistable element has no inputs: when power comes up it settles into one state by chance and stays there. To be useful the state must be forced to a chosen value, so extra logic is added. A flip-flop is a bistable device with inputs that stays in a given state as long as power is applied and until input signals make it change. Its inputs are of two types:

  • Asynchronous (direct) inputs — a sufficiently long signal change produces an almost immediate change of state (after a short propagation delay).
  • Synchronous inputs — they do not change the state by themselves; they matter only when a control signal, usually called the enable or clock, also occurs.

A bistable element is a circuit with two stable states, made from two cross-coupled NOT gates (output of each gate feeds the input of the other). With Q = 0 the loop gives Q = 1 and with Q = 1 it gives Q = 0; both conditions are self-consistent, so the circuit keeps whichever one it is in as long as power is on. 5.2.1 The SR (set–reset) latch — two cross-coupled NOR gates

The SR latch (Fig 31) is two NOR gates cross-coupled. The upper gate has the reset input R and produces Q; the lower gate has the set input S and produces Q. When S = R = 0 each NOR gate acts as a NOT gate, so the circuit is the basic bistable element of §5.1 and simply keeps its state.

Working, row by row.

  • S = 0, R = 0. Both NOR gates behave as inverters, the latch is the bistable element, and it holds its present state (Q+ = Q).
  • S = 0, R = 1 (reset). R = 1 forces the upper NOR output to 0, so Q = 0. That 0 is fed to the lower gate whose other input S is also 0, so Q = 1. The latch is reset whatever its earlier state. If R then returns to 0 the latch keeps the reset state, because the Q = 1 fed back to the upper gate holds Q at 0.
  • S = 1, R = 0 (set). By the mirror argument the lower NOR gives Q = 0, the upper NOR then gives Q = 1: the latch is set, and stays set when S returns to 0.
  • S = 1, R = 1. Both NOR outputs become 0, so Q and Q are not complementary. The real difficulty appears when the inputs return to 0: if one input goes to 0 before the other, the last input to remain at 1 decides the final state (our simulation: R falls first ⇒ Q = 1; S falls first ⇒ Q = 0); if both return to 0 at the same instant the latch may enter its metastable state and the final state is unpredictable. Hence S = R = 1 is the forbidden (not-recommended) input.

Because a 1 on S or R activates the latch (sets or resets it) the NOR latch is called active-high. Since a change on S or R can immediately change the outputs, S and R are asynchronous (direct) inputs.

5.2.2 Application of the SR latch: switch debouncer

When a mechanical switch changes position its contact does not move cleanly: the springy contact bounces, touching and leaving the terminal several times before settling. A keyboard key or push-button that bounces would be read as several key presses. An SR latch removes the effect (Fig 32).

Fig 32. Switch debouncer: a single-pole double-throw switch drives the S and R inputs of an SR latch; pull-down resistors keep the inputs at 0 whenever the contact is touching neither terminal. Below: simulated waveforms.

Operation. Two pull-down resistors hold S and R at logic 0 whenever the moving contact is not touching A or B (switch “open”). Moving the contact from B to A: first R goes to 0 (the contact leaves B; the latch holds), then S becomes 1 when the contact reaches A ⇒ the latch is set and Q = 1. If the contact bounces off A, S falls back to 0 — but S = R = 0 is the hold condition, so Q stays 1. Every later bounce also leaves Q unchanged. The same happens in reverse when the switch moves back to B (the latch is reset once). The output therefore makes one clean transition per switch operation. In the simulated trace (above) A = 001010111 and B = 110000000 give a latch output Q = 001111111.

qb 1 Q343 marks
Explain the difference between a latch and a flip-flop.
Answer

A latch is a level-sensitive storage element: its output responds (after the propagation delay) to changes at the inputs for the whole time it is enabled, i.e. it is transparent, and the timing of the output change is not controlled. A flip-flop (master-slave or edge-triggered) is a clocked element whose output changes only at a definite instant of the control signal — the falling edge of the pulse for a master-slave flip-flop, or one chosen edge (rising or falling) for an edge-triggered flip-flop — and is insensitive to the information inputs at all other times. Latches are therefore used for simple storage/holding (switch debouncer, input buffering), while flip-flops are used wherever the same element is read and written in one clock period, such as registers and counters.

(Givone groups both under the word “flip-flop”: latches, pulse-triggered and edge-triggered flip-flops are the three classes.)

Differentiate between an SR latch and a D latch.
Answer

The SR latch has two inputs, S (set) and R (reset); it can set, reset or hold, but the input S = R = 1 (NOR type) is forbidden because both outputs go to 0 and the final state is unpredictable when the inputs are released together. The D latch is thus a SR latch made “safe” with an inverter, and it is the basic storage cell for one bit of data.

5.3

Timing Considerations

Propagation delay, minimum pulse width, setup & hold time, transparency and metastability.

The function tables of §5.2 say what a latch does, not when. Real gates have delays, and proper operation requires certain time constraints to be met. These are stated here for latches but apply equally to the master-slave and edge-triggered flip-flops of the next sections. The usual tool is the timing diagram: a graph of the input and output transitions of a device as a function of time.

5.3.1 Propagation delay

The propagation delay is the time between a change at an input and the resulting change at an output. It is different for each input–output pair and for the two directions: tPLH (output going low → high, 0→1 in positive logic) and tPHL (high → low). Manufacturers specify them. Delays are measured between the 50% points of the (finite-slope) edges. The outputs of a latch therefore never change instantly and not simultaneously: in the NOR SR latch of Fig 37, the output on the gate that sees the input changes first and the other output follows one gate delay later.

Fig 37. Propagation delays in the NOR SR latch (set pulse, then reset pulse); gate-level simulation with a fixed gate delay.

Timing diagrams also show the behaviour of the forbidden input: with S = R = 1 both Q and Q are 0, and if S and R change from 1 to 0 simultaneously the response is unpredictable (shaded in textbook figures) until a later set or reset input restores a defined state.

5.3.2 Minimum pulse width

A latch input must be held active for at least the manufacturer's minimum pulse width tw(min) for the change to take place reliably. A pulse that is too narrow may be ignored, or may leave the latch in its metastable state; in either case the result is unpredictable.

Fig 38. Minimum pulse width: a set pulse shorter than t_w(min) gives an unpredictable (shaded) response.

5.3.3 Setup time and hold time

For a gated latch to latch the correct value, the data input must be stable around the instant the enable falls. The minimum time D must be held fixed before the latching edge is the setup time tsu; the minimum time it must stay fixed after the edge is the hold time th (Fig 39a). If D changes inside this window the output may be wrong or the device may go metastable. The identical constraints apply to the information inputs (J, K, D, T, S, R) of master-slave and edge-triggered flip-flops, relative to their active clock edge (Fig 39b).

Fig 39. Setup and hold windows around the latching edge: (a) gated D latch (C falls), (b) positive-edge-triggered flip-flop (C rises).

5.3.4 Transparency and metastability — why timing matters

Because a latch is enabled for a whole interval, a change at D while C = 1 passes straight to Q (Fig 36). This transparency is acceptable for storage but not where the output of one storage element feeds back to its own (or a neighbour's) input within the same enable period, as in registers and counters — that is what flip-flops are for. Violating setup/hold or minimum-pulse-width rules can produce metastability: an output that sits at an invalid level for an unpredictable time before settling to 0 or 1, which can propagate wrong values into the rest of the system.

6.1

Master-Slave Flip-Flops

Two-latch construction, SR / JK / D / T versions, and the race-around condition.

Latches are transparent: while enabled their output follows the information inputs, so the stored value cannot be read and rewritten in the same enable period. Often the output change must instead be tied to the change of a control (clock) signal, so that the present state can be sensed while new information is entered. Two classes of flip-flop achieve this: master-slave (also called pulse-triggered) flip-flops — this section and §6.2 — and edge-triggered flip-flops (§6.3).

Clarifying the syllabus wording

Your syllabus lists Master-Slave Flip-Flops and Pulse-Triggered Flip-Flops as two items, but the source text (Givone) treats them as one topic: “master-slave flip-flops (pulse-triggered flip-flops)”. This guide keeps them as two sections so the syllabus order is respected: §6.1 covers the structure and operation (SR, JK, D, T, race-around); §6.2 covers the pulse-triggered behaviour (0’s and 1’s catching, data lockout, symbols).

6.1.1 Principle and the master-slave SR flip-flop

A master-slave flip-flop is two cascaded sections, each able to store a bit: the first is the master, the second the slave. Information is entered into the master on one edge (or level) of the control signal and transferred to the slave on the next. In its simplest form each section is a latch. The master-slave SR flip-flop (Fig 40) uses two gated SR latches and an inverter: the master is enabled by C, the slave by C̄ (through the inverter), and the master outputs QM, Q̄M drive the slave's S and R inputs.

Fig 40. Master-slave SR flip-flop: two gated SR latches and an inverter, with its logic symbol (the L-shaped mark is the postponed-output indicator).

Sequence of events during one clock pulse (Fig 41):

  1. C = 0. The master is disabled, so S and R are ignored. The inverter keeps the slave enabled, so the slave simply equals the master and the output is steady.
  2. C starts to rise (t1). The slave is disabled first: it is cut off from the master but keeps the old state. The master is still disabled.
  3. C is high (t2 … t3). The master is enabled and, being a gated SR latch, follows S and R. The slave is disabled, so none of this reaches Q.
  4. C falls (t3). The master is disabled first and latches its new state. Only then (t4) is the slave enabled and it takes over the master's state — the output changes at the falling edge of the clock.
Fig 41. Enable phases of the master and the slave. For short intervals around each clock edge both are disabled — this is essential to the operation.

6.1.2 The master-slave JK flip-flop

The undefined S = R = 1 case of the SR flip-flop is a nuisance. The master-slave JK flip-flop (Fig 43) permits both information inputs to be 1 and makes the output toggle. J behaves like S (it sets) and K like R (it resets). The change from the SR design is two AND gates in front of the master that steer using the slave's present state: SM = J·Q and RM = K·Q, where Q, Q are the outputs of the slave.

Fig 43. Master-slave JK flip-flop: two gated SR latches, two feedback AND gates and an inverter; function table on the right.

Why it toggles. Take Q = 1, J = K = 1, C = 0. The feedback gives SM = J·Q̄ = 0 and RM = K·Q = 1, so when C rises the master is reset while the slave (disabled) stays at 1; when C falls the slave copies the master and Q becomes 0. Starting with Q = 0 the AND gates give SM = 1, RM = 0: the master is set, and the slave follows at the falling edge, so Q becomes 1. Either way the output complements. For J = 1, K = 0 both AND outputs are 0 when Q = 1 (nothing to set) and SM = 1 when Q = 0, so the flip-flop ends in the 1-state whatever it was (set); J = 0, K = 1 similarly resets; J = K = 0 holds.

6.1.3 Master-slave D and T flip-flops

Putting an inverter between the S and R inputs of a master-slave SR flip-flop gives the master-slave D flip-flop (S = D, R = D̄); the D value present at the end of the pulse is transferred to the output, so Q+ = D. Tying the J and K terminals of a master-slave JK flip-flop together (T = J = K) gives the master-slave T flip-flop: it toggles with every clock pulse when T = 1 and holds when T = 0 (Q+ = T ⊕ Q).

6.1.4 Race-around condition

Not in your materials — added for syllabus completeness

Neither Givone nor your unit 3b slides name the race-around condition; they describe the closely related 0’s/1’s catching (§6.2) and Problem 6.10 (a gated JK latch). Because CIE-II 24-25 Q4a and qb Q35–36 ask for it directly, it is written out in full here. The simulations are from this guide's code.

Where it arises. Suppose a JK flip-flop is built as a level-triggered (gated) latch: AND gates form S = J·C·Q and R = K·C·Q and drive an SR latch directly (Fig 45). The outputs Q and Q are fed straight back to the input gates, so the latch is not isolated from its own output.

Fig 45. Level-enabled JK latch: Q and Q-bar are fed back directly to the input AND gates, which is what causes race-around.

The problem. Let J = K = 1 and let C go high. The latch toggles after one propagation delay. That new output is fed back through the AND gates, which now steer the opposite way, so after a further delay it toggles again — and this repeats for as long as C remains 1. If the clock pulse width tw is longer than the loop propagation delay td, the output oscillates roughly tw/td times during one pulse, and the final state when C falls depends on whether that number is odd or even — it is unpredictable in practice. This is the race-around condition; it occurs only for J = K = 1 (toggle) and only in level-triggered JK flip-flops.

Cures.

  • Make tw < td (a very narrow clock pulse): works in principle but is impractical because the pulse would also have to exceed the minimum pulse width, and the gate delays vary.

  • Edge-triggered JK flip-flop (§6.3): inputs are sampled only at one edge, so the output cannot recirculate during the clock level.

6.2

Pulse-Triggered Flip-Flops

Pulse-triggered behaviour, 0's and 1's catching, and the data-lockout remedy.

A flip-flop whose behaviour depends on both edges and on the period during which the control signal is high — information enters on the leading edge or throughout the pulse and the output is postponed to the trailing edge — is called pulse-triggered. The master-slave flip-flops of §6.1 are the standard examples. Their logic symbol carries the postponed-output indicator (the L-shaped mark at the output terminals; see Fig 51), meaning “the output changes when the control signal returns to 0”.

6.2.1 0’s catching and 1’s catching

The master of a master-slave JK flip-flop is a latch: it is enabled during the entire time C = 1. If J or K changes during that time the master responds, even for a short glitch, and the (wrong) value is passed to the slave at the falling edge.

  • 0’s catching. The slave (and so the flip-flop) is in the 1-state. A momentary 1 on K while C = 1 resets the master; the slave is reset when C falls — the flip-flop has “caught” a 0 even though K has returned to 0 and J was 0 at the pulse start. Once the master is reset, a later 1 on J in the same pulse cannot set it again, because the feedback from the slave (Q̄S = 0) keeps the J-gate output at 0.
  • 1’s catching. The mirror case: the flip-flop is in the 0-state and a momentary 1 on J while C = 1 sets the master, and the slave is set at the falling edge.
Fig 47. 0's and 1's catching in a master-slave JK flip-flop (Givone Fig 6.15, reproduced by simulation). Pulse 2: K blips high while J = 0 → Q is cleared (0's catching). Pulse 3: J rises mid-pulse → Q is set (1's catching).

In the figure: pulse 1 — J = 1, K = 0 at the start of the pulse: the master sets and Q goes to 1 at the falling edge (normal operation). Pulse 2 — J = 0 but K goes 1 for a short time in the middle of the pulse: QM falls and Q falls at the falling edge — 0’s catching (the only reason for the reset is a glitch). Pulse 3 — Q is 0, K = 1 throughout, J rises late in the pulse: QM rises when J does and Q rises at the falling edge — 1’s catching. Pulse 4 — J = K = 1 with Q = 1: the master resets and Q toggles to 0. 6.2.2 Avoiding the catching problem

  1. Timing discipline: hold J and K constant for the whole interval in which the master is enabled — changes only while C = 0 (this is what the function table assumes). The effect of the inputs then appears at the output delayed by one pulse.
  2. Use an edge-triggered flip-flop (§6.3): J and K are read only at one edge, so glitches elsewhere are ignored.
  3. Use a master-slave flip-flop with data lockout (§6.2.3).

6.2.3 Master-slave flip-flop with data lockout

Where a delayed output is wanted (so that it is a master-slave type) but catching must be avoided, the master should accept the information on one edge only and transfer it on the opposite edge. In the data-lockout construction (Fig 48) the master is a positive-edge-triggered JK flip-flop and the slave is an SR latch, with an inverter between them. Information enters the master only at the rising edge; changes of J or K while C = 1 are disregarded (the master is “locked out”). At the falling edge the slave copies the master, so the output is delayed until the end of the pulse.

Fig 48. Master-slave JK flip-flop with data lockout: +edge-triggered JK master, SR-latch slave, inverter between the two sections.

6.3

Edge-Triggered Flip-Flops

+edge and −edge D flip-flops, asynchronous inputs, edge JK and T, level vs edge.

In a master-slave flip-flop the master is enabled for the whole high period of C, which allows catching. An edge-triggered flip-flop avoids it: it reads the information inputs only at one edge of the clock — the triggering edge — and is blind to them at all other times, including while C is steady at 1 or 0. The inputs are sampled instead of continuously interrogated, and because the output depends only on the propagation delays of the gates, it responds almost immediately after the triggering edge. (In a master-slave flip-flop the effect of the inputs appears delayed until the falling edge.)

6.3.1 Positive-edge-triggered D flip-flop

The D flip-flop (Fig 49) uses six NAND gates. Gates 5 and 6 form an SR latch of the NAND type (the output stage; it responds to 0s on its inputs S̄ and R̄); gates 1–4 steer the information so that the latch is set or reset only at the rising edge of C. The equations are: g1 = NAND(g2, g4), g2 = NAND(g1, C) = S̄, g3 = NAND(g2, C, g4) = R̄, g4 = NAND(g3, D).

Fig 49. Positive-edge-triggered D flip-flop built from six NAND gates (Givone Fig 6.18a).

Operation.

  • C = 0. Gates 2 and 3 output 1 whatever D is, so S̄ = R̄ = 1 and the output latch (g5, g6) holds. With D = 0, g4 = 1 and g1 = 0; with D = 1, g4 = 0 and g1 = 1 — the gates are “armed” to respond to the value of D.
  • Rising edge, D = 0. All three inputs of g3 (g2 = 1, C = 1, g4 = 1) become 1, so g3 = R̄ = 0, while g2 stays 1 (since g1 = 0): S̄ = 1, R̄ = 0 ⇒ the latch is reset. The 0 at the output of g3 is fed back to g4, forcing g4 = 1 — later changes of D while C = 1 cannot affect anything.
  • Rising edge, D = 1. Now g1 = 1, so when C rises g2 = NAND(1, 1) = 0 = S̄, and g3 stays 1 (g4 = 0): S̄ = 0, R̄ = 1 ⇒ the latch is set. The 0 on g2 holds g1 and g3 at 1, so later changes of D while C = 1 are ineffectual.
  • C returns to 0. S̄ and R̄ return to 1 and the latch keeps the state captured at the rising edge.

Thus only the rising edge makes the flip-flop look at D, and the value sampled is the D present just before the edge (setup time) and held just after it (hold time). The gate-level simulation confirms this for all combinations of D before and after the edge:

7.1.1 Registers and shift registers

A register is a group of flip-flops used to store binary information temporarily. An n-bit register consists of n flip-flops and can store n bits of data; it can be in any of 2n 0-1 combinations, and the combination it holds is its state (content). Registers that are capable of moving information position-wise on the occurrence of a clock signal are called shift registers: a shift register is a sequential circuit that stores binary data and shifts it from one flip-flop to the next on every clock pulse.

Shift registers are classified in two ways:

  • By direction of data movement: unidirectional (shift right only, or shift left only) or bidirectional (can shift either way — the universal shift register).
  • By the manner in which data is entered and taken out: serially (one bit at a time on one line, one bit per clock pulse) or in parallel (all bits at once, one line per bit). This gives the four basic modes SISO, SIPO, PISO and PIPO (§7.1.3).

7.1.2 Applications of registers and shift registers

Registers

  1. Temporary data storage — intermediate data during arithmetic and logical operations in a CPU.
  2. Data transfer between different sections of a processor.
  3. Instruction storage — the Instruction Register (IR) holds the instruction being executed.
  4. Address storage — the Memory Address Register (MAR) holds the address of the memory location to be accessed.
  5. Accumulator — holds intermediate results of arithmetic/logic operations.
  6. Buffering — holds data during transfer between devices working at different speeds.
  7. Processor operations — general-purpose registers hold operands, addresses and intermediate results.

Shift registers

  1. Serial-to-parallel conversion (SIPO) of data received from a communication channel.
  2. Parallel-to-serial conversion (PISO) for transmission.
  3. Temporary data storage during digital operations.
  4. Time-delay circuits — a digital delay by shifting through successive flip-flops.
  5. Sequence generation — ring and Johnson counters (Unit III).
  6. Arithmetic — serial addition; multiplication / division by shifting.
  7. Data transfer between digital systems and communication interfaces.
  8. Digital signal processing — digital filters, delay lines.
  9. LED display control — running-light patterns.
  10. Pseudo-random sequences — linear-feedback shift registers (LFSRs) for testing and communication (see the XOR-feedback register in §7.2.2).
Exam tip

Shift-left by one position multiplies an unsigned binary number by 2 and shift-right divides it by 2 — the reason shift registers appear in serial multipliers and dividers.

7.1.6 Parallel-in registers: PISO and PIPO

To load all bits at once, every D input is fed by a 2:1 multiplexer (Fig 59). The common select line of the multiplexers acts as the mode-control pin, Load/Shift:

  • Load/Shift = 0 → shift mode. MUX input 0 is selected: FF3 receives the serial input and every other flip-flop receives the Q of its left neighbour, so on each clock pulse the data is shifted out (right) one bit at a time at Q0.
  • Load/Shift = 1 → load mode. MUX input 1 is selected: the parallel inputs P3P2P1P0 are loaded into all the flip-flops at once when the clock pulse is applied.

Used as PISO: load once (Load/Shift = 1), then shift (Load/Shift = 0) and read Q0. Used as PIPO: load and read all four outputs Q3…Q0 together — no shifting. The same circuit can also run as SISO or SIPO by keeping Load/Shift = 0.

7.1.7 Circular shift register

A circular shift register is a shift register in which the output of the last flip-flop is connected back to the input of the first flip-flop, forming a closed loop. The data stored in the register therefore circulates continuously from one flip-flop to the next with every clock pulse; nothing is lost, it is only re-oriented. In a 4-bit circular shift register (Fig 59b):

  • four D flip-flops are connected in cascade;
  • the output of the last flip-flop (Q0) is fed back to the input of the first flip-flop (D of FF3);
  • all flip-flops receive a common clock signal.
Fig 59b. 4-bit circular shift register (shift right with Q0 fed back to the serial input).

Example. Starting from 1011: 1101 → 1110 → 0111 → 1011 after 1, 2, 3, 4 pulses — the content returns to 1011 after four pulses (n pulses for an n-bit register). This loop with a single 1 circulating is the ring counter, and with Q̄0 fed back instead it is the Johnson (twisted-ring) counter of Unit III.

7.1.8 Bit shift register and word shift register

Not in your materials — added for syllabus completeness

A bit shift register is the register above: each stage holds one bit and one bit moves per stage per clock pulse (n bits = n flip-flops in a chain). A word shift register has stages that are themselves multi-bit registers (e.g. a bank of 8 or 16 flip-flops per stage); on each clock pulse an entire word moves to the next stage, so n words need n×(word width) flip-flops and parallel data paths. Bit shift registers do serial/parallel conversion and delay; word shift registers are used as FIFO buffers and delay lines for whole samples.

  • Industrial use of a bit shift register: a conveyor reject-tracking system — a bit (1 = defective item) is shifted along the register once per item position, so the reject gate fires exactly when the flagged item reaches the gate; also serial communication (UART) and I/O expansion (SIPO/PISO chips).
  • Industrial use of a word shift register: a FIFO data buffer between a sensor/ADC and a processor, or a bottling-line queue storing a whole record (batch code, weight) per item that moves down the line.

Givone P6.10text problem
A proposed gated JK latch (AND gates J·C·Q̄ and K·C·Q driving an SR latch). Discuss the problems that can be encountered and the constraints under which proper JK flip-flop behaviour is achieved.
Answer

This is the level-triggered JK latch of §6.1.4 (Fig 45). Problem: for J = K = 1 and C = 1 the output toggles repeatedly (race-around); the final state is unpredictable. Constraints: proper JK (toggle) behaviour requires the clock pulse width to be shorter than the loop propagation delay (and longer than the minimum pulse width) — practically impossible to guarantee — or J = K = 1 must not be applied with a long pulse; the real cures are master-slave or edge-triggered construction. Givone P6.16text problem
Show that for the positive-edge-triggered D flip-flop of Fig 6.21a it resets when PR = 1 and CLR = 0 regardless of C and D, and sets when PR = 0 and CLR = 1.
Answer

PR and CLR are active-low and feed the output NAND SR latch (gates 5, 6) and also gates 1, 2, 4. CLR = 0 forces the gate that produces Q̄ to 1 (a NAND with a 0 input), and with PR = 1 the other output gate then gives Q = 0: reset. Because CLR also reaches gates 1, 2 and 4, the result holds even while C = 1 and whatever D is. Symmetrically, PR = 0 forces Q = 1 and (with CLR = 1) Q̄ = 0: set. With PR = CLR = 1 the flip-flop is the plain edge-triggered D flip-flop of §6.3.1. (Checked on the NAND SR output latch: S̄ = 0 → Q = 1; R̄ = 0 → Q = 0.)

Givone P6.17text problem
Show that the master-slave configuration of two gated D latches (first latch enabled by C̄, second by C) is described by the positive-edge-triggered D flip-flop function table of Fig 6.18.
Answer
  1. While C = 0 the first (master) latch is enabled: its output follows D. The second (slave) latch is disabled and holds the old Q.
  2. When C rises, the master is disabled and holds the value D had just before the edge, while the slave becomes enabled and copies that held value: Q = D(before the edge) — the value sampled at the rising edge.
  3. While C = 1 the master is closed, so changes of D cannot reach Q; when C falls the slave closes and the master re-opens, but the slave holds. So Q changes only at the rising edge, to the D present just before it — exactly the +edge D function table. (Verified against an edge-triggered model on 200 random D/C streams.)
