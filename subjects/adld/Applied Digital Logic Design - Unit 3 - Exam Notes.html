Binary Ripple Counters

Counter, state, modulus, counting sequence; the 4-bit binary ripple counter, its timing and its settling-time limitation.

A counter is another example of a register: a collection of flip-flops whose primary function is to produce a specified output pattern sequence. For this reason a counter is also a pattern generator. The sequence may count the occurrences of an event, or each pattern may be used to control a portion of a digital system (each pattern is then associated with a distinct operation the system must perform).

  • Each 0-1 combination stored in the flip-flops (the output pattern) is a state of the counter.
  • The total number of states is its modulus; a counter with m distinct states is a modulus-m (mod-m) counter.
  • The order in which the states appear is the counting sequence, usually drawn as a directed graph called a state diagram (Fig 1): each node Si is a state and the arrows show the order in which the states occur.
Fig 1. State diagram of a mod-m counter (Givone Fig 6.30): one node per state, one arrow per count pulse.

1.1 Binary ripple counters

Counters whose counting sequence is that of the binary numbers are binary counters. An n-flip-flop binary counter has modulus 2n, because there are 2n combinations of n bits. A binary up-counter counts 00…0 to 11…1 (0 to 2n−1) and then repeats; a binary down-counter counts in the reverse order, 11…1 down to 00…0.

Construction (Fig 2). A 4-bit binary up-counter is built from four positive-edge-triggered T flip-flops (a JK flip-flop with J and K tied together and called T; each positive transition on C makes it toggle). The output Qi is the i-th order bit of the count. The inputs to the counter are a count-enable signal (applied to every T input) and the count pulses, which are applied only to the C input of the lowest-order flip-flop Q0. The C input of every other flip-flop is connected to the Q output of the previous-order flip-flop.

Fig 2. Four-bit binary ripple counter with positive-edge-triggered T flip-flops (Givone Fig 6.31a).

Operation. Assume the counter starts in 0000 and count enable = 1.

  1. The positive edge of the 1st count pulse toggles Q0 to 1. Its Q0 output goes 1→0 — a negative edge — so Q1 is not affected. State = 0001.
  2. The 2nd pulse toggles Q0 back to 0. Now Q0 goes 0→1, a positive edge on the C input of Q1, so Q1 toggles to 1. The change of Q1 gives a negative edge to Q2, which is unaffected. State = 0010.
  3. The 3rd pulse toggles only Q0: 0011. The 4th pulse returns Q0 to 0, which toggles Q1 back to 0, which in turn toggles Q2 to 1: 0100.
  4. The count continues to 1111. The next pulse returns Q0 to 0, which returns Q1 to 0, which returns Q2 to 0, which finally returns Q3 to 0: the counter is back in 0000 and repeats.

In short: Q0 toggles on every count pulse; Qi toggles whenever Qi−1 goes from 1 to 0 (its complement rises). Fig 3 is the resulting timing diagram (delays ignored).

Why “ripple”? Settling time

It is called a ripple counter because a change of state of the Qi−1 flip-flop is what toggles the Qi flip-flop — the effect of a count pulse must ripple through the counter. Ripple counters are also called asynchronous counters (the flip-flops are not clocked together). Since every flip-flop has a propagation delay tpd, the stabilised count appears only after the ripple is complete. The worst case is the change 11…1 → 00…0, where the toggle must propagate through the entire counter:

worst-case settling time (n-stage ripple counter) = n × t_pd e.g. MOD-32 ripple counter: n = 5 flip-flops (2^5 = 32), t_pd = 50 ns settling = 5 × 50 ns = 250 ns → f_max = 1 / 250 ns = 4 MHz (if the count must be read after every pulse)
Fig 4. The 16th pulse with t_pd = 10 per flip-flop: intermediate (false) states 1110, 1100, 1000 appear before 0000 (event simulation).

Note the contrast in Givone: the allowable count-pulse rate of an asynchronous counter is set by its first stage only — once the first flip-flop has changed, it can accept the next pulse even though the change has not finished propagating. But the count is not available for use until the ripple is complete. Synchronous counters (§2) remove this settling problem.

1.3 Mod-N ripple counters with asynchronous clear

The CIE-II (Dec 2024) scheme designs an asynchronous mod-6 up counter from a 3-bit ripple counter: 3 flip-flops (since 23 = 8 ≥ 6), ripple clocking as above, and a NAND gate that detects the first unwanted state 110 (inputs Q2 and Q1, the bits that are 1 in 110) and drives the active-low asynchronous CLEAR of every flip-flop. The counter counts 000, 001, …, 101; as soon as the next pulse makes it 110, the NAND output goes 0 and immediately clears it to 000. The state 110 exists only momentarily (a glitch), so the visible sequence is 0–5. A ripple decade counter uses the same idea with a NAND detecting 1010 (Q3, Q1). See the worked versions in Solved problems.

1.4 From the 2026 faculty notes: the four mod-8 ripple configurations

The faculty notes build the same mod-8 (3-bit) ripple counter four ways from T flip-flops with T = 1 (the count enable line drives every T input: 1 = count, 0 = hold). In every version the input clock goes only to the first flip-flop, and the output of each stage is the clock of the next. Two choices decide the counting direction: which edge the flip-flops trigger on, and whether the next stage is clocked from Q or from Q.

Why. In an up count a bit must toggle when the bit below it goes 1 → 0 (a falling edge of Q). A negative-edge stage clocked from Q sees exactly that edge. A positive-edge stage sees it only if it is clocked from Q, because a falling edge on Q is a rising edge on Q. Swapping either choice (edge type or Q/Q) turns an up counter into a down counter. Exam tipDraw the timing diagram by marking the triggering edges on each flip-flop's own clock input first: the CLK edges for Q0, the edges of Q0 (or Q0) for Q1, and so on. Then toggle at each mark. The flip-flop that receives the external clock is always the LSB.

Frequency division

A T flip-flop with T = 1 toggles once per clock edge, so its output has half the clock frequency: it is a divide-by-2 (mod-2) counter. n flip-flops in a ripple chain give fout = fin / 2n. When counters of modulus M and N are cascaded (the output of one clocks the other), the overall modulus is M×N and fout = fin / (M·N).

Mod-N counters by skipping states (faculty examples)

A counter of modulus 2, 4, 8, 16 … needs only the right number of flip-flops. For any other modulus (mod-5, 6, 7 …) the faculty notes start from the next higher binary counter and skip the unwanted counts. A gate decodes the first unwanted state N and drives the asynchronous clear of every flip-flop, so state N lasts only a few nanoseconds (the small glitch on the waveform) before the counter is forced to 0. To design mod-N, decode the value N: the bits that are 1 in N go to the NAND gate, and any bit that is 0 goes in through an inverter.

Drawbacks of ripple counters, and fmax

  1. Propagation delay and speed limit. Each flip-flop must wait for the one before it, so the delays add up. With n flip-flops of delay tpd, the count settles only n·tpd after the clock edge. The next clock must not arrive before then: Tclock > n·tpd, so fmax = 1 / (n·tpd).
  2. Asynchronous nature. The outputs do not change together, and the transient states (glitches) make the counter hard to synchronise with the rest of a digital system.
  3. Only the natural binary sequence is easy. Other sequences (BCD, or any random order) need extra hardware and are slower. A ripple counter can only count up or down in sequence, never in an arbitrary order.

Its advantage is simplicity: no gates are needed between the stages, only the Q or Q connections.

Answer

The NAND output goes low, clearing the counter, the moment Q3 = Q2 = 1, i.e. when the count reaches 1100 (12). Count 1100 exists only for an instant, so the last count you can observe is 1011 = 11. The counter behaves as a mod-12 counter, 0 to 11 (checked by simulation).

CIE 2025 (propagation delay + design)2 + 6
Discuss the concept of propagation delay in ripple counters and how it affects the maximum operating frequency. Design a negative-edge (↓) triggered MOD-6 asynchronous up counter using T flip-flops.
Answer

Propagation delay is the time between a transition at a flip-flop's input (the clock edge) and the resulting change at its output. It is never zero, because the internal transistors take time to switch. In a ripple counter a change must pass through the flip-flops one after another, so the delays accumulate, up to n·tpd for n flip-flops. For reliable operation the next clock edge must not arrive until every flip-flop has settled: Tclock ≥ n·tpd, i.e. fmax = 1/(n·tpd).

Design. Mod-6 needs 3 flip-flops (22 < 6 ≤ 23), with TA = TB = TC = 1. The clock goes to flip-flop A (the LSB). Because the flip-flops are negative-edge triggered, each next stage is clocked from the previous Q output (up counting; see the table in §1.4). Reset logic decodes the first invalid state 110: a gate on C·B (with an inverter or bubble on A if a full decode is wanted) drives the active-low clear of all flip-flops, so 110 resets the counter to 000. The sequence is 000, 001, 010, 011, 100, 101, then 000 (6 states, checked by simulation). The faculty answer draws the reset logic with an OR gate on the complemented outputs, B + C. By De Morgan this equals NAND(B, C), and NAND gates work just as well.

Synchronous Binary Counters

All flip-flops clocked together; the toggle rule, the AND-chain variation, parallel load, mod-10 and cascading.

The settling-time problem of ripple counters is avoided in synchronous counters: the count pulses are applied directly to the C inputs of all the clocked flip-flops, so all the flip-flops change simultaneously, after the propagation delay of a single flip-flop.

2.1 The toggle rule and the basic synchronous binary counter

Look at the binary counting sequence (table in §1): on every count pulse the lowest-order flip-flop Q0 must toggle, and any other flip-flop Qi must toggle exactly when all its lower-order flip-flops Qi−1, …, Q0 are in their 1-states. Fig 5 realises this with T flip-flops and AND gates:

T0 = CE T1 = CE·Q0 T2 = CE·Q0·Q1 T3 = CE·Q0·Q1·Q2 (CE = count enable; all C inputs = count pulses)
Fig 5. Four-bit synchronous binary counter (Givone Fig 6.32): the AND gate in front of each T input detects that all lower stages are 1.

While count enable = 1 the counter follows the binary sequence 0000, 0001, 0010, 0011, …, 1111, 0000 (simulated from the equations). Since the pulses reach every flip-flop directly, the only delay between a count pulse and the new count is one flip-flop propagation delay.

Drawbacks. The AND gate feeding the p-th flip-flop has p inputs, so a long counter needs AND gates with many inputs; and the output of the p-th flip-flop must drive n−p AND gates, so the low-order flip-flops drive many gates (loading problems).

2.2 Variation with 2-input AND gates

The AND gate in front of Qi has exactly the inputs of the gate in front of Qi−1 plus Qi−1. So each gate can be fed by the previous gate's output and Qi−1 only (Fig 6). Every AND now needs just two inputs and every flip-flop output drives only one gate. The price: the enabling signal passes through a chain of AND gates, so gate delays accumulate between count pulses and limit the count-pulse rate. All flip-flops still change together, one tpd after the edge.

2.3 Parallel load, mod-m counters and cascading

If a synchronous binary counter can be loaded in parallel with an initial number before counting, a mod-2n counter can serve as a mod-m counter (m < 2n). Givone's 4-bit counter with parallel load (Fig 6.34) uses JK flip-flops (easier to handle the load inputs) and two enables, both synchronised with the positive edge of the count pulses:

A carry output CO is 1 whenever the counter is in 1111 and in count mode (count enable = 1, load enable = 0).

Mod-10 (decimal) counter (Fig 7). Tie D3…D0 to 0 and feed an AND gate that detects the count 1001 into the load-enable input. The first state with Q0 = Q3 = 1 (starting from 0000) is 1001, so the AND output becomes 1 there and, because load has precedence, the next pulse loads 0000. The sequence is 0000, 0001, 0010, 0011, …, 1001, 0000 (verified).

Fig 7. Synchronous mod-10 counter from the 4-bit counter with parallel load (Givone Fig 6.35): load 0000 when Q3·Q0 = 1.

Cascading (Fig 8). Two 4-bit counters make an 8-bit counter: the carry output of the counter holding the four least-significant bits drives the count enable of the counter holding the four most-significant bits. When the low counter reaches 1111 its CO = 1, so on the next pulse the low counter returns to 0000 while the high counter is incremented by 1. Commercial MSI counters of both types exist, some also counting down.

2.4 From the 2026 faculty notes: reading a given synchronous counter

The faculty notes show the 4-bit synchronous binary (mod-16) counter exactly as in §2.1: T flip-flops on one common clock with count enable (1 = enable, 0 = disable). Q0 toggles on every clock, Q1 toggles when Q0 = 1, Q2 toggles when Q0Q1 = 1, and Q3 toggles when Q0Q1Q2 = 1. Short questions then give a small synchronous circuit and ask for its sequence. The method is always the same:

  1. Write each flip-flop input as an expression of the present state (read it off the gates).
  2. Put it into the characteristic equation: Q+ = JQ + KQ (JK), Q+ = T ⊕ Q (T), Q+ = D (D).
  3. Tabulate present state → next state for every state, then follow the arrows from the given start state.

Counters Based on Shift Registers

Ring counter, twisted-ring (Johnson) counter and its odd-modulus variation; decoding each state.

A digital system's operation is divided into a sequence of time periods. One way to identify them is a binary counter plus a decoder. The alternative is a non-binary counter whose patterns make each state easy to detect, at the cost of more flip-flops. Two such counters, built on the shift register, are the ring counter and the switch-tail (twisted-ring, Johnson) counter.

3.1 Ring counter

A ring counter is a circular shift register initialised so that only one flip-flop is 1 and the others are 0. Each count pulse shifts the single 1 to the adjacent flip-flop. Self-Correcting Counters

Unused states, power-up and noise; the self-correcting test, the complete state diagram, and how to guarantee self-correction.

The mod-6 counter of §4 does not use the states 100 and 111. Once a counter is built, these states nevertheless have definite next states (whatever the chosen expressions produce). They matter because:

  • when power is first applied, the initial states of the flip-flops are unpredictable, so the counter may start in 100 or 111;
  • one remedy is to initialise the counter through the asynchronous (preset/clear) inputs before use — but noise can still push it into an unused state later.
Definition (Givone)

A counter in which all the states not included in the original counting sequence eventually lead to the normal counting sequence after one or more count pulses is said to be self-correcting. To avoid having the counter “hang up”, it should always be designed as self-correcting.

5.2 Why a counter may fail to self-correct, and the cure

  • Counters with no unused states are always self-correcting (e.g. a full mod-2n binary counter).
  • It is the assignment made to the don't-cares of the unused states, when the expressions are minimised, that can make a counter not self-correcting — e.g. an unused state may lead to itself, or two unused states may lead to each other, forming a loop outside the count (the counter “hangs up”).
  • Guarantee: specify the next state of every unused state before drawing the K-maps (e.g. send each unused state to the initial state). The cells are then no longer don't-cares, the expressions may be slightly larger, but self-correction is guaranteed.

Structure and Operation of Clocked Synchronous Sequential Networks

Synchronous vs asynchronous, the clocked structure and how it operates, Mealy and Moore models.

A sequential network is one whose outputs at any instant depend not only on the present inputs but also on the past history (sequence) of inputs; it must therefore have memory. The information preserved is the network's internal (secondary) state, physically the signals at a set of points inside the network. The inputs plus the present state determine the outputs (Fig 19).

Fig 19. General model of a sequential network (Givone Fig 7.1).

Sequential networks fall into two classes:

  • Synchronous: behaviour is determined by the signal values only at discrete instants of time, defined by special timing signals; the memory may change only at those instants. (The counters of Part 1 are synchronous networks whose instants are the triggering edges of the count pulses.)
  • Asynchronous: it is the order in which inputs change that matters, and changes may occur at any time. (Givone Ch.9 — not in this syllabus.)

6.1 Structure of a clocked synchronous sequential network

The most common timing method is a single master clock applied to the control inputs of all the flip-flops that form the memory, so all flip-flops receive it simultaneously. Such networks are clocked synchronous sequential networks (Fig 20). The memory is a set of clocked flip-flops (edge-triggered; master-slave can also be used); combinational logic generates the next-state and output signals from the inputs and the present state.

Fig 20. Structure of a clocked synchronous sequential network (Givone Fig 7.2).

Operation

  1. The clock is periodic, with one positive and one negative edge per period; its edge (edge-triggered flip-flops) or its pulse (pulse-triggered) is the triggering / active time.
  2. New inputs and the new present state are applied to the combinational logic; because gates have propagation delays, the flip-flop inputs reach their final values at different times. Only after the final values are reached is the active time of the clock allowed to occur.
  3. At the active time all flip-flops change state at the same time (common clock). The process then repeats: new inputs, then the synchronising clock.
  4. Each flip-flop undergoes at most one state change per clock period: output changes caused by the clock cannot cause another change until the next period (which is why edge-triggered or master-slave flip-flops are used).

The single master clock gives synchronisation and prevents many timing problems.

Modelling Clocked Synchronous Sequential Network Behaviour

From word description to state diagram/table: serial adder (Mealy and Moore), sequence recognizers, a Moore parity example.

Synthesis (design) is the reverse of analysis: from a word description, (1) construct a state table or state diagram — the model; (2) reduce it to the minimum number of states (§9); (3) code the states in binary to get a transition table; (4) build an excitation table for the chosen flip-flops; (5) find the excitation and output expressions; (6) draw the logic diagram. Modelling is the first step and has no standard technique: you must understand the specification and know how to interpret a state table/diagram. Two approaches: define the states a priori (the information about the past that must be kept), or build the diagram step by step, adding a state whenever a new past history must be remembered. Too many states is harmless (reduction removes them) but the table must be finite.

8.1 Serial binary adder as a Mealy network

Two operands arrive serially on x and y, least significant bit first, before each clock edge; the sum appears serially on z (block diagram: inputs x, y, clock; output z). Except for the first pair, each sum bit depends on the two operand bits and whether a carry was generated by the previous pair. So exactly that must be remembered: A = “no carry from the previous order” (initial state, I.S.) and B = “a carry was generated”.

  • In A the sum bit is the plain sum of x and y: 00/0, 01/1, 10/1 stay in A (no carry); 11 gives sum 0 with a carry, so 11/0 goes to B.
  • In B the sum is one more than x + y: 01 and 10 give 0 with a carry (stay in B), 11 gives 1 with a carry (stay in B), and 00 gives 1 with no carry → back to A (00/1).

8.3 A sequence recognizer (step-by-step construction)

Specification. Single input x, single output z. x = 0100010010010010000000011 z = 0000001000000100000000001 (reproduced by simulating Table 7.9)

8.6 From the 2026 faculty notes: sequence detectors (Mealy and Moore)

A sequence detector (also called a sequence recogniser) is a clocked sequential circuit with one serial input x and one output z. Whenever a particular bit pattern appears in the input stream, z becomes 1. Sequence detectors are used in digital communication, for example to find frame-start patterns. Two versions exist:

  • Overlapping: the last bits of one detected pattern may be reused as the first bits of the next. For 1101, the input 1101101 contains two detections: 1101 and 1101 sharing the middle 1.
  • Non-overlapping: after a detection the detector starts again from scratch, so 1101 1101 1101 gives three separate detections.

Design steps used in the faculty notes:

  1. State diagram. State a is the initial state (nothing useful seen yet). Each later state remembers how much of the pattern has been matched: b = first bit seen, c = first two bits seen, and so on. On every input, go to the state for the longest part of the pattern that the last few inputs still match (this is what makes the detector overlapping).
  2. Number of flip-flops: the smallest n with 2n ≥ number of states (n = ⌈log2 m⌉).
  3. State assignment: a = 00, b = 01, c = 10, d = 11 (unused codes are don't-cares).
  4. State table / excitation table with present state, input, next state and output.
  5. K-map simplification of each flip-flop input (with D flip-flops, D = next state) and of the output.
  6. Circuit: flip-flops on a common (synchronous) clock plus the gates.
Faculty rule of thumb: number of statesFor an n-bit pattern, a Mealy detector needs n states and a Moore detector needs n + 1 (3 bits → 3 or 4, 4 → 4 or 5, 5 → 5 or 6). The Moore machine needs the extra state because its output must be stored in a state of its own (the “pattern found” state). This holds for single-pattern detectors like the ones below. Machines that recognise several patterns at once, such as the 0110/1001 recogniser in §8.4, need more states.

Mealy to Moore conversion

A Moore state can produce only one output, so split every Mealy state that is entered with different outputs into one copy per output. State Table Reduction

9.1 Why reduce?

During modelling more states may be defined than necessary (Table 7.10 has 7 states, Table 7.11 has 15 for the same behaviour). In synthesis the state symbols are replaced by binary codes, and the minimum number of code bits — flip-flops — is ⌈log2(number of states)⌉. Reducing 9 states to 8 saves a flip-flop (4 → 3); reducing 7 to 5 does not (3 either way). Even with the same number of flip-flops, fewer states leave more don't-cares, usually giving simpler logic. (A reduction does not guarantee a cheaper realisation, but the potential saving motivates it.)

Two networks are equivalent if they produce identical output sequences for every possible input sequence. The goal is the minimal state table: the one with the fewest states equivalent to the original. Here the state table is assumed completely specified (every next state and output given).

9.2 Equivalent states

Experiment (Fig 33): start one copy of a network in state p and another in state q, apply the same arbitrary input sequence to both. p and q are equivalent (indistinguishable), p ≡ q, iff for all input sequences the two output sequences are identical; otherwise they are distinguishable.

Theorem 7.1

Two states p and q of a clocked synchronous sequential network are equivalent if and only if for each combination of values of the input variables (1) their outputs are identical and (2) their next states are equivalent.

Proof sketch. Let ω(q, x) be the output and δ(q, x) the next state for input symbol x, and ω(q, I) the output sequence for an input sequence I. If: for input xJ, ω(p, xJ) = ω(p, x)ω[δ(p, x), J]; condition (1) makes the first symbols equal and condition (2) makes the remaining sequences equal for every J, so p ≡ q. Only if: if p ≡ q then ω(p, xJ) = ω(q, xJ) for all x, J; comparing first symbols gives (1); comparing the rest gives δ(p, x) ≡ δ(q, x), i.e. (2).

Using it by hand (Table 7.13 below): (A, B) are not equivalent — for x = 1 their outputs are 0 and 1. Added from the 2026 faculty notes

  • Ripple direction: ↑-edge + Q tap = down; ↑-edge + Q = up; ↓-edge + Q = up; ↓-edge + Q = down. The flip-flop that receives the external clock is the LSB.
  • fout = fin/2n; cascaded mod-M and mod-N: fin/(M·N). fmax = 1/(n·tpd) (5 × 20 ns → 10 MHz; 10 × 3 ns → 33.33 MHz).
  • Mod-N by clearing: decode N (the 1-bits go to the NAND, 0-bits through inverters) and drive the active-low clear. The last observable count is N − 1.
  • Self-correcting: every unused state reaches the count in one or more clocks. Otherwise the counter has hung up (lock-out). To guarantee it, specify the unused next states before the K-maps. Self-starting = enters the loop from any state; free-running = the loop contains all states.
  • Analysis in 3 steps: equations → state table → state diagram.
  • Detectors: an n-bit pattern needs n Mealy states or n + 1 Moore states; flip-flops = ⌈log2(states)⌉. 111 Mealy: D1 = xQ0 + xQ1, D0 = xQ̄1Q̄0, z = xQ1. 111 Moore: D0 = xQ̄0 + xQ1, z = Q1Q0.
  • Mealy vs Moore: output from state + input vs state only; fewer vs more states; output string n vs n + 1 symbols; output asynchronous vs synchronous with the clock.
